The `yarn initialize` script wraps the Open Mercato CLI `mercato init` command and delivers a ready-to-run workspace. It installs dependencies, prepares generated module artifacts, applies database migrations, seeds baseline RBAC data, and populates demo CRM content (companies, people, deals, activities, todos) unless you disable it with `--no-examples`. Enable `--stresstest` to tack on a synthetic, high-volume dataset that includes additional companies, pipeline deals, activities, and notes — all wired with realistic custom field values and a live progress bar.

## Usage

```bash
yarn initialize [--org=<name>] [--email=<address>] [--password=<value>] [--roles=<csv>] [--no-examples] [--no-demo-users] [--stresstest] [--lite] [-n <count>] [--count=<count>] [--reinstall|-r]
```

Ensure `DATABASE_URL` points to the Postgres instance you want to initialize before running the command.

Supply a unique superadmin password through `OM_INIT_SUPERADMIN_PASSWORD` in the environment or `.env`, or through `--password`. There is no default password. For example, replace the placeholder in this `.env` entry with a password generated for this deployment:

```dotenv
OM_INIT_SUPERADMIN_PASSWORD="<unique password from your password manager>"
```

The value must satisfy the configured `OM_PASSWORD_*` policy. Missing, empty, known-placeholder, and policy-invalid values abort initialization before dependency installation, generation, migrations, or reinstall table deletion. This applies in development and production. The legacy `--skip-password-policy` and `--allow-weak-password` init flags cannot bypass this validation.

The cross-platform `@open-mercato/starter` prepares a unique password in a new root `.env` and mirrors it to `apps/mercato/.env`. It preserves configured values on reruns, and startup summaries direct you to retrieve `OM_INIT_SUPERADMIN_PASSWORD` from those private files. Newly created files have `0600` permissions on POSIX systems; existing permissions are preserved. Its generated 68-character value satisfies the default policy; supply your own value if a custom minimum length requires more.

## Options

| Option | Description | Default |
| --- | --- | --- |
| `--org`, `--orgName` | Name of the organization that will be created. | `Acme Corp` |
| `--email` | Superadmin login email. Companion `admin@…` and `employee@…` accounts are also provisioned. | `superadmin@acme.com` |
| `--password` | Superadmin password; overrides `OM_INIT_SUPERADMIN_PASSWORD` and must satisfy the configured password policy. | Required through flag or environment |
| `--roles` | Comma-separated list of roles ensured before user creation. | `superadmin,admin,employee` |
| `--skip-password-policy`, `--allow-weak-password` | Legacy init flags; cannot disable superadmin password validation. The separate `mercato auth setup` command retains its own flag behavior. | No bypass |
| `--no-examples` | Skip demo CRM seeders (companies, people, deals, activities, todos). Alias: `--no-exampls`. | off |
| `--no-demo-users` | Skip seeding the derived `admin@…`/`employee@…` demo accounts — only the `--email` superadmin account is created. | off |
| `--stresstest` | Generate a high-volume synthetic CRM dataset (contacts, companies, deals, activities, notes) in addition to the curated examples. | off |
| `--lite` | When paired with `--stresstest`, skips deals, activities, notes, and custom fields for faster high-volume contact generation. | off |
| `-n`, `--count`, `--stress-count`, `--stresstest-count` | Number of synthetic contacts to create when `--stresstest` is enabled. | `6000` |
| `--reinstall`, `-r` | Drops every table in the target database before bootstrapping. Requires a valid `DATABASE_URL`. | off |

## Environment Defaults

When you omit CLI flags, the init flow will read environment defaults for the seeded accounts:

| Variable | Description | Default |
| --- | --- | --- |
| `OM_INIT_SUPERADMIN_EMAIL` | Superadmin login email used when `--email` is not provided. | `superadmin@acme.com` |
| `OM_INIT_SUPERADMIN_PASSWORD` | Unique, policy-compliant superadmin password used when `--password` is not provided. Known placeholders are rejected. | Required through flag or environment |
| `OM_INIT_ADMIN_EMAIL` | Derived admin account email override. | `admin@<superadmin-domain>` |
| `OM_INIT_EMPLOYEE_EMAIL` | Derived employee account email override. | `employee@<superadmin-domain>` |
| `OM_INIT_ADMIN_PASSWORD` | Derived admin account password override. When unset, production generates a random 16-char base64url password; other environments retain the demo default. | Production: randomly generated; otherwise: `secret` |
| `OM_INIT_EMPLOYEE_PASSWORD` | Derived employee account password override. When unset, production generates a random 16-char base64url password; other environments retain the demo default. | Production: randomly generated; otherwise: `secret` |
| `OM_INIT_GENERATE_RANDOM_PASSWORD` | **Deprecated, no-op.** Derived passwords are randomized in production when overrides are unset; setting the flag prints a one-time deprecation warning. | _(unused)_ |

`yarn initialize` passes `--include-demo-users` to `mercato auth setup` so the derived `admin@…` / `employee@…` demo accounts are seeded as part of the dev/demo bootstrap. Standalone callers of `mercato auth setup` must opt in themselves; without that flag, no demo accounts are seeded. Pass `--no-demo-users` to `mercato init`/`yarn initialize` to skip them too — for example on a production bootstrap where only the `--email` superadmin account should exist.

## What the Command Does

Before the steps below, initialization validates the required superadmin password. A read-only existing-user probe may run first for normal initialization so Docker can recognize an initialized database and continue its migration path. Reinstall validates credentials before any database access. Failed password validation prevents database creation or mutation and the initialization steps below.

1. Installs workspace dependencies with `yarn install`.
2. Runs code generators directly (entity IDs, module registry, entities, DI, API client) — no process spawning.
3. Applies all per-module migrations via the internal migration engine.
4. Bootstraps the application (registers modules, DI registrars, entity IDs).
5. Seeds configuration defaults (`configs restore-defaults`).
6. Runs `auth setup` to create the tenant, organization, and user accounts specified.
7. Seeds feature toggle defaults (`feature_toggles seed-defaults`).
8. If tenant ID is available, seeds tenant-scoped roles (`auth seed-roles`).
9. If organization and tenant IDs are detected:
   - Seeds customer dictionaries (`customers seed-dictionaries`).
   - Seeds catalog units (`catalog seed-units`).
   - Seeds availability schedules.
   - Seeds encryption defaults (if `TENANT_DATA_ENCRYPTION` is enabled).
   - Seeds catalog price kinds, tax rates, sales statuses, adjustment kinds, shipping methods, and payment methods.
   - Unless `--no-examples` is present, seeds demo CRM data (`customers seed-examples`), catalog examples, sales examples, and example Todos (`example seed-todos`).
   - When `--stresstest` is present, seeds synthetic contacts, companies, deals, activities, and notes with custom fields (and a progress bar) via `customers seed-stresstest`. Add `--lite` to focus on raw contacts without the heavier extras.
   - Enables default dashboard widgets (`dashboards seed-defaults`).
   - Triggers vector search reindex and query index reindex.

On success, the command prints a boxed summary with created accounts and their passwords.

:::info Performance Improvement
The init command now calls CLI handlers directly instead of spawning separate processes for each step. This significantly reduces initialization time by eliminating ~25+ process spawns and maintaining shared state (DI container, entity IDs, etc.) across all operations.
:::

## Reinstall Mode

When `--reinstall` is present the command:

- Loads env variables via `dotenv/config`.
- Connects to the configured database and drops all tables in the `public` schema using `CASCADE`.
- Continues with a clean bootstrap and reseeds example data (unless you add `--no-examples`).

Use this mode for destructive resets in development. **Never run it against production databases.**

## Troubleshooting

- **Missing or rejected superadmin password** — set `OM_INIT_SUPERADMIN_PASSWORD` to a unique password satisfying the configured policy, then retry. Policy-bypass init flags do not permit weak or placeholder credentials.
- **Deployment initialized with an earlier default password** — review privileged accounts and rotate their passwords through the existing account-management or password-reset flow. Changing the bootstrap environment variable does not change existing account passwords; do not use `--reinstall` to rotate them.
- **Missing `DATABASE_URL`** — the command aborts before performing database work. Export the variable or place it in `.env`.
- **Dependency install fails** — run `yarn install` manually to inspect the error, then re-run `yarn initialize`.
- **Migrations fail** — confirm the database credentials and ensure the target user can create tables. The CLI stops on the first failure so you can address the issue before re-running.
