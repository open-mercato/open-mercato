`yarn db:migrate` is an alias for `mercato db migrate`: it runs MikroORM migrations for every enabled module in alphabetical order, and nothing else.

In particular it does **not** run generators and does **not** install custom entity or field definitions. If you need the schema *and* the definitions and grants the current code declares — the usual case after upgrading Open Mercato or enabling a module — use [`yarn mercato upgrade`](./upgrade), which applies migrations and then reconciles those definitions under the same lock.

```bash
# Migrations only
yarn db:migrate

# Equivalent
yarn mercato db migrate
```

## Usage

```bash
yarn db:migrate

# Wait at most 60s for a concurrent migrate or upgrade run to finish
yarn mercato db migrate --lock-timeout=60

# Local runs against a database nothing else is touching
yarn mercato db migrate --no-lock
```

The command relies on `DATABASE_URL` for database connectivity.

## Serialization

Migrations run while holding `pg_try_advisory_lock(0x4F4D, 0x5547)` — the same lock [`mercato upgrade`](./upgrade) takes. A solo run is unaffected. A second run started while a first is in flight waits, retrying every 5 seconds, and then exits non-zero naming the lock instead of applying the same migration twice.

| Option | Description | Default |
| --- | --- | --- |
| `--lock-timeout=<seconds>` | How long to retry lock acquisition before exiting non-zero. | `600` |
| `--no-lock` | Skip lock acquisition. For local use only — never a deploy. | off |

The lock connection must use a direct database URL, never a transaction-mode pooler; see [Advisory Locking](./upgrade#advisory-locking) for why, and for the stuck-lock runbook.

## When to Run

- After pulling new migrations from version control.
- After upgrading to a newer Open Mercato version.
- Immediately after `yarn db:generate` to apply fresh diffs.
- During CI to guarantee the schema is aligned before running tests or seeding fixtures.
- If you already have data and users, prefer `yarn db:migrate` over `yarn initialize` (which seeds data and may abort when users exist).

## Output

The script prints progress for each module with a progress bar showing migration application status (e.g., `[====================] 3/3`). Any failure aborts the remaining steps so you can resolve the issue safely.

## Troubleshooting

- **Migration errors** — inspect the failing module's migration file in `packages/<module>/src/modules/<module>/migrations`. You can retry once the issue is resolved.
- **Definitions still missing after a successful migrate** — expected: this command only applies schema. Run [`yarn mercato upgrade`](./upgrade), or `yarn mercato entities install` on its own.
- **Lock timeout** — another migrate or upgrade run holds the lock. See the [stuck-lock runbook](./upgrade#stuck-lock-runbook).
- **Long-running migrations** — consider running `yarn db:migrate` with `NODE_ENV=production` pointing to a managed database that has appropriate resources.
