# Usage & Integration

## Sales-provided templates

The Sales module contributes three template variants through its `document-generators.ts` convention file. The rendering package remains domain-independent.

| Template | ID | Resource | Document type |
|----------|----|----------|---------------|
| Order Invoice | `sales.order-invoice` | `sales.order` | invoice |
| Order Invoice (Markdown) | `sales.order-invoice-markdown` | `sales.order` | invoice |
| Sales Offer | `sales.offer` | `sales.quote` | offer |

Both templates use React-PDF's built-in Helvetica font and authoring tokens exported by the rendering package. Their services, translations, templates and detail widgets are owned by Sales; the plugin provides the registry, rendering infrastructure and authoring toolkit.

To contribute templates from another module, extend `BaseDocumentService` imported from `@open-mercato/shared/modules/document-generators` and export its entries through that module's `document-generators.ts` convention file. Sales-provided templates remain owned by Sales and are registered only when Sales is enabled.

---

## Registering templates from another module

Templates are registered via a **convention file** named `document-generators.ts` at the root of any module (sibling of `index.ts`, `acl.ts`, etc.). The `mercato generate registry` step scans all loaded modules for this file and adds its templates to the global registry automatically.

Template IDs share one global namespace and must use `<module>.<template>` namespacing, for example `my_module.invoice`. Registration is intentionally strict: any second registration of the same ID, including an otherwise identical entry, stops bootstrap with a diagnostic naming both modules. This prevents duplicate generator output or module evaluation from silently shadowing a template.

No widget or injection-table entry is needed for Sales orders and quotes because Sales already owns those document tabs. Other resources must contribute their own thin widget.

A fully working implementation is available in the [Document Generators examples](./examples).

### Step 1 — Create a `DocumentService`

Place it in `src/modules/<your_module>/document-generators/services/`.

```ts
// src/modules/my_module/document-generators/services/my-module-invoice-document-service.ts
import { BaseDocumentService, type TemplateDataContext } from '@open-mercato/shared/modules/document-generators'
import { buildDocumentFilename, formatDate } from '@open-mercato/document-generators/modules/document_generators/utils'
import type { AppContainer } from '@open-mercato/shared/lib/di/container'

export class MyModuleInvoiceDocumentService extends BaseDocumentService {
  readonly id = 'my-module-invoices'    // globally unique — convention: <module>-<category>s
  readonly label = 'My Module Invoices'
  readonly module = 'my_module'         // top-level module name — used for grouping in the UI
  readonly resourceKind = 'sales.order' // must match ctx.resourceKind on the target detail page

  constructor() {
    super()

    this.registerTemplate({
      id: 'my_module.invoice',
      label: 'My Module Invoice',
      description: 'Standard invoice for my module orders.',
      documentType: 'invoice',
      format: 'pdf',
      tags: ['invoice', 'my_module'],
      filename: ({ data }) => buildDocumentFilename(data, 'invoice', 'pdf'),
      load: () =>
        import('../templates/invoice/my-module-invoice').then(
          (m) => ({
            type: 'react-pdf' as const,
            component: m.MyModuleInvoiceDocument as unknown as React.ComponentType<{ data: Record<string, unknown> }>,
          })
        ),
    })
  }

  override async fetchData({ data }: { data: unknown }, { container }: { container: AppContainer }) {
    const record = data as { id: string }
    // const service = container.resolve('myOrderService')
    // return service.retrieve(record.id)
    throw new Error(`fetchData not implemented (id: ${record.id})`)
  }

  toTemplateData({ data, locale, translate }: { data: unknown } & TemplateDataContext): Record<string, unknown> {
    const r = data as { id: string; number: string }
    return {
      labels: { invoice: translate?.('my_module.documents.invoice.invoice') ?? 'my_module.documents.invoice.invoice' },
      document: { id: r.id, number: r.number, date: formatDate(new Date().toISOString(), locale) },
      seller:   { name: '', company: '', email: '' },
      client:   { name: '' },
      lines:    [],
      totals:   { subtotal: 0, tax: 0, total: 0, currency: 'PLN' },
    }
  }

  override resourceId({ data }: { data: Record<string, unknown> }): string {
    return (data.document as { id: string }).id
  }
}
```

### Step 2 — Create the template component

Place it in `src/modules/<your_module>/document-generators/templates/<category>/<template-id>/pdf/index.tsx`.

```tsx
import {
  Document,
  Page,
  StyleSheet,
  Text,
  View,
} from '@open-mercato/document-generators/modules/document_generators/providers/react-pdf'
import { OpenMercatoLogo } from '@open-mercato/document-generators/modules/document_generators/templates/shared/components/Logo'
import { colors } from '@open-mercato/document-generators/modules/document_generators/templates/shared/theme'

const s = StyleSheet.create({
  page:  { paddingHorizontal: 52, paddingVertical: 48, fontSize: 10, fontFamily: 'Helvetica', color: colors.text },
  title: { fontSize: 28, fontWeight: 600 },
})

export function MyModuleInvoiceDocument({ data }: { data: Record<string, unknown> }) {
  const doc = data.document as { number: string; date: string }

  return (
    <Document>
      <Page size="A4" style={s.page}>
        <View style={{ flexDirection: 'row', justifyContent: 'space-between', marginBottom: 28 }}>
          <Text style={s.title}>Invoice {doc.number}</Text>
          <OpenMercatoLogo />
        </View>
        {/* seller, client, line items, totals … */}
      </Page>
    </Document>
  )
}
```

> Helvetica is built into React-PDF, so templates do not need to register or bundle local font files. The React-PDF dependency remains inside the rendering plugin.

---

### Step 3 — Create the convention file

```ts
// src/modules/my_module/document-generators.ts
import { MyModuleInvoiceDocumentService } from './document-generators/services/my-module-invoice-document-service'

const service = new MyModuleInvoiceDocumentService()

export const templates = service.getEntries()
export default templates
```

---

### Step 4 — Regenerate

```bash
yarn generate
```

The template now appears in the Sales-owned documents tab on matching sales order detail pages.
