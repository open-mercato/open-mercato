# API Reference

## REST Endpoints

All endpoints require authentication. Preview and listing require `document_generators.view`; generation requires `document_generators.generate`. Both rendering endpoints load and normalize the template through `templateRegistry`, then pass its format-neutral render input to `DocumentRenderer`.

---

### `GET /api/document-generators/templates`

Returns all templates registered by application modules through `document-generators.ts`.

```jsonc
// Response
[
  {
    "id": "order-invoice",
    "label": "Order Invoice",
    "description": "Standard invoice for sales orders.",
    "module": "sales",
    "resourceKind": "sales.order",
    "documentType": "invoice",
    "tags": ["invoice", "order"]
  }
]
```

Use this endpoint to build custom template pickers or to verify that your registered templates are visible to the registry.

---

### `GET /api/document-generators/templates/options`

Returns only the sorted, unique values available to template catalogue filters. Use this endpoint to populate filter controls without downloading the full template catalogue.

```jsonc
// Response
{
  "resourceKinds": ["sales.order", "sales.quote"],
  "formats": ["md", "pdf"]
}
```

---

### `POST /api/document-generators/preview`

Renders the selected template for preview. PDF output is displayed in an iframe; Markdown output is displayed as text.

**No side effects** — no logging, no events, no persistence. Safe to call repeatedly as the user switches between templates.

```jsonc
// Request body
{
  "template_id": "order-invoice",
  "data": { "id": "order_01JXYZ..." }
}
```

```
// Response
Content-Type: application/pdf
<binary stream>
```

---

### `POST /api/document-generators/generate`

Renders the selected template and streams it to the browser as a file download.

**Has side effects** — every successful render creates a best-effort generation-history row. Resource kind, canonical ID, and the human-readable label are derived exclusively from normalized document data on the server.

```jsonc
// Request body
{
  "template_id": "order-invoice",
  "data": { "id": "order_01JXYZ..." }
}
```

```
// Response
Content-Type: application/pdf
Content-Disposition: attachment; filename="invoice-1042.pdf"
<binary stream>
```

**Typical client-side usage:**

```ts
import { apiCall } from '@open-mercato/ui/backend/utils/apiCall'
import { downloadBlob } from '@open-mercato/document-generators/modules/document_generators/utils'

const { result, error } = await apiCall(
  '/api/document-generators/generate',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      template_id: template.id,
      data: record,
    }),
  },
  { parse: (res) => res.blob() },
)

if (!error && result) {
  const url = URL.createObjectURL(result)
  downloadBlob(url, template.id)
  URL.revokeObjectURL(url)
}
```

---

### Preview vs generate — decision guide

| | `/preview` | `/generate` |
|---|---|---|
| Purpose | Display in iframe | File download |
| Side effects | None | Best-effort generation history |
| When to call | On template card click | On the download button click |
| Resource identity | Derived server-side | Derived server-side and persisted |
| Safe to call repeatedly | Yes | Avoid |

## TypeScript Exports

Runtime services and UI are exported from `@open-mercato/document-generators`. Neutral template contracts and `BaseDocumentService` are exported from `@open-mercato/shared/modules/document-generators`. React-PDF primitives come from `@open-mercato/document-generators/modules/document_generators/providers/react-pdf`; template assets are imported directly from their files under `modules/document_generators/templates/shared`.

### `BaseDocumentService` (`@open-mercato/shared/modules/document-generators`)

Abstract base class. Extend once per category of documents in your module.

| Member | Description |
|--------|-------------|
| `id` (abstract) | Globally unique service identifier. Convention: `<module>-<category>s` |
| `label` (abstract) | Human-readable name shown in the admin page |
| `module` (abstract) | Top-level module name — used for grouping (`'sales'`, `'my_module'`) |
| `resourceKind` (abstract) | Framework resource kind matching the detail page (`'sales.order'`, `'sales.quote'`) |
| `registerTemplate(entry)` | Registers a template with its format-specific `filename` and `load` handlers |
| `getEntries()` | Returns all registered templates ready for the global registry |
| `toTemplateData({ data, locale, translate })` (abstract) | Maps the enriched server record to template data using the active locale and request translator |
| `fetchData(input, ctx)` | Server-side hook called before `toTemplateData`. Override to load related data via DI. Default: passes data through unchanged |
| `filename(input)` | Derives the download filename from normalized data. Default: `'document.pdf'` |
| `resourceId(input)` (abstract) | Derives the required canonical source-record id from normalized server-side data |

### `DocumentRenderer`

Selects a rendering service by the string value in `DocumentRenderInput.format`. The template registry does not know which formats exist; it only prepares `{ format, source, data }`.

```ts
const { locale, t } = await resolveTranslations()
const template = await templateRegistry.load({ id, data }, { container, auth, locale, translate: t })
const document = await new DocumentRenderer().render(template.render)
```

### `formatDate(isoString, locale)` (`@open-mercato/document-generators/modules/document_generators/utils`)

Formats an ISO 8601 string using the locale's natural date convention and a fixed UTC time zone. There is no default locale; pass the locale received by `toTemplateData`.

### `formatMoney(amount, currency, locale)` (`@open-mercato/document-generators/modules/document_generators/utils`)

Formats a numeric amount with `Intl.NumberFormat`, including locale-correct separators, currency symbol and symbol placement.

### `buildDocumentFilename(data, prefix, extension)` (`@open-mercato/document-generators/modules/document_generators/utils`)

Builds a format-specific filename from normalized `data.document.number`, falling back to `{prefix}.{extension}` when the number is unavailable. It is an optional convenience helper; templates may provide any custom `filename` implementation that fits their output contract.

### `TemplatesList`

React component that renders the template list for a given resource. Normally rendered automatically by the core sales module.

| Prop | Type | Description |
|------|------|-------------|
| `record` | `{ id: string }` | Minimal record — full data is fetched server-side |
| `filter` | `TemplateFilter` | Scopes the list by `resourceKind`, `documentType`, or `tags` |

### `OpenMercatoLogo` (`@open-mercato/document-generators/modules/document_generators/templates/shared/components/Logo`)

Pre-built React-PDF component rendering the Open Mercato brand mark. Use directly inside template components.

### `colors`, `borders`, `spacing`

Design tokens from the PDF template toolkit, exported by `@open-mercato/document-generators/modules/document_generators/templates/shared/theme`. Importing them has no runtime side effects.

### Types

| Type | Description |
|------|-------------|
| `TemplateMeta` | UI-facing descriptor: id, label, module, resourceKind, documentType, tags |
| `TemplateEntry` | Full descriptor — `TemplateMeta` plus runtime handlers |
| `TemplateRegistryEntry` | Neutral runtime hooks; `load()` returns a format-neutral `DocumentTemplateSource` |
| `TemplateFilter` | Plugin UI filter: `{ resourceKind?, documentType?, format?, tags? }` |
| `DocumentTemplateEntry` | Shape passed to `registerTemplate()`; requires `format`, `filename`, and `load` |
| `DocumentTemplateSource` | Shared extensible source shape: `{ type: string; [key: string]: unknown }` |
| `DocumentRenderInput` | Plugin runtime input: `{ format: string, source, data }` |
| `LoadedTemplate` | Format-neutral prepared template and its render input |
| `RenderedDocument` | Rendered bytes plus filename, MIME type, format, template, and source-resource metadata |
| `templateRegistry` | Global singleton registry — use only for custom rendering pipelines outside the standard endpoints |

Format-specific types are colocated with their engines: `PdfRenderInput` and `ReactPdfTemplateSource` live in `pdf-rendering-service/types.ts`; `MarkdownRenderInput` and `MarkdownTemplateSource` live in `markdown-rendering-service/types.ts`. Adding another format does not change the shared contracts.
