# Contributing

## Local setup

The package is developed in the Open Mercato monorepo. The Mercato app is used to verify changes end-to-end.

```bash
# from the monorepo root

# build the package in watch mode
yarn workspace @open-mercato/document-generators watch

# in a separate terminal — start the development app
yarn dev
```

After making changes, navigate to a sales order or quote in the sandbox to verify templates render correctly.

## Reference implementation

The [examples page](./examples) and the downloadable source under `apps/docs/static/examples/document-generators/` contain a working invoice integration that mirrors the structure a consuming module should produce:

```
examples/
  document-generators.ts                        ← convention file (auto-discovery entry point)
  invoice/
    services/
      example-invoice-document-service.ts  ← concrete DocumentService
    templates/
      example-invoice/
        index.tsx                          ← React-PDF template component
        types.ts                           ← typed data shape
  widgets/                                 ← reference only — illustrates the widget pattern
                                             do NOT copy for Sales orders/quotes; Sales owns those tabs
```

Domain templates belong to their owning module. Changes to this package should be limited to registry, rendering formats, reusable authoring primitives, API/UI infrastructure, or history.

## Package structure

```
src/
  index.ts                              ← public exports
  modules/document_generators/
    api/document-generators/
      templates/route.ts                ← GET /api/document-generators/templates
      preview/route.ts                  ← POST /api/document-generators/preview
      generate/route.ts                 ← POST /api/document-generators/generate
    components/
      TemplatesList.tsx                 ← format-neutral template picker
      PreviewPanel.tsx                  ← dialog with iframe preview + download button
    lib/
      interfaces.ts                     ← format-neutral runtime types
      template-registry.ts              ← global singleton registry; knows no concrete formats
    services/
      document-renderer.ts              ← dispatches through a format-to-renderer map
      pdf-rendering-service/
        types.ts                        ← PdfRenderInput + ReactPdfTemplateSource
        pdf-rendering-service.ts        ← renders React-PDF sources to bytes
      markdown-rendering-service/
        types.ts                        ← MarkdownRenderInput + MarkdownTemplateSource
        markdown-rendering-service.ts   ← renders Markdown sources to bytes
    templates/
      shared/
        theme.ts                        ← colors, borders and spacing tokens
        components/Logo.tsx             ← OpenMercatoLogo component
    generators.ts                       ← picks up module-provided document-generators.ts files

packages/shared/src/modules/document-generators/
  index.ts                              ← public shared module entrypoint
  lib/interfaces.ts                    ← neutral declarations; format and source type are strings
  services/
    base-document-service.ts            ← neutral BaseDocumentService
    types.ts                            ← DocumentTemplateEntry

packages/core/src/modules/sales/document-generators/
  services/                             ← Sales-owned fetching and normalization
  templates/                            ← Sales-owned order and quote documents
```

## Testing

The package has two independent test layers.

### Unit tests (Jest)

Fast, isolated tests with mocked dependencies. They live in domain-colocated `__tests__/` directories (`lib/__tests__`, `services/__tests__`, `utils/__tests__`) and need no running app.

```bash
# from the monorepo root
yarn workspace @open-mercato/document-generators test
```

### Integration tests (Playwright)

Engine navigation and neutral API tests live with this package. Sales-specific listing, preview, generation and history scenarios live under `packages/core/src/modules/sales/__integration__/document-generators/`. Both are auto-discovered by the shared Playwright config.

They require a **running sandbox** with the `sales` module, a database, and an `admin` account. The base URL comes from `BASE_URL` (default `http://localhost:3000`).

```bash
# from the monorepo root — start the sandbox first (see "Local setup" above)

# run every module's integration suite
yarn test:integration

# run only this module's tests (positional path filter)
npx playwright test --config .ai/qa/tests/playwright.config.ts packages/document-generators

# run the neutral engine navigation test, fail-fast while iterating
npx playwright test --config .ai/qa/tests/playwright.config.ts \
  packages/document-generators/src/modules/document_generators/__integration__/TC-PDF-005.spec.ts --retries=0
```

> Note: `yarn test` (Jest) never runs the `.spec.ts` files, and `yarn test:integration` (Playwright) never runs the `.test.ts` files — the two toolchains are fully separate.

Run artifacts (HTML report, JSON, traces) are written to `.ai/qa/test-results/` and are git-ignored.

## How to add a domain template

1. In the owning module, create a service extending `BaseDocumentService` imported from `@open-mercato/shared/modules/document-generators`
2. Create its PDF or Markdown template beside that service; PDF templates import primitives from `@open-mercato/document-generators/modules/document_generators/providers/react-pdf` and toolkit assets directly from `modules/document_generators/templates/shared`
3. Export the service entries from the owning module's root `document-generators.ts`
4. Update the documentation example under `apps/docs/static/examples/document-generators/`
5. Run `yarn generate`, then verify the owning module's detail widget and render flow
