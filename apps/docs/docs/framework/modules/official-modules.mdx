# Modules catalog

[Open Mercato Modules](https://modules.openmercato.com) lists the modules you can add to an app without forking the platform: official `@open-mercato/*` packages and community and third-party packages. Every entry is read from the published package. Its page shows what the module adds (pages, API routes, entities, events, environment variables), its license, the Open Mercato versions it was built for, and the result of a nightly install in a fresh app.

Before you build a feature, check whether it already exists. Modules that ship inside `@open-mercato/core` are listed under [Built-in](https://modules.openmercato.com/built-in). Many of them are already on in a new app; the module's page says when you need [`module enable`](/cli/module-enable).

## Find a module

- Search [modules.openmercato.com](https://modules.openmercato.com) for what you need, for example `ksef`, `exchange rates`, or `when a deal is won`.
- Browse a category, for example [Integrations & Data Sync](https://modules.openmercato.com/c/integrations-sync) or [Payments & Finance](https://modules.openmercato.com/c/payments-finance).
- Let your coding agent ask the same data before it writes code: [For agents](https://modules.openmercato.com/for-agents) lists the read-only tools, the `om-find-module` skill, and the plain-text files agents can read.

## Install a module {#installing-an-official-module}

Each module page has an install box with the exact command for the version the catalog recommends, for example:

```bash
yarn mercato module add @fastwhitecat/integration-ksef-direct@0.1.8 --allow-third-party

# Apply any new migrations introduced by the module
yarn db:migrate
```

- Keep the exact version from the module page. When the module is verified on your Open Mercato line, it is the version that installed cleanly there. Otherwise check the module page's status for your line before you install: the box can show a version that is untested or broken there.
- Packages outside `@open-mercato/*` need `--allow-third-party`. The flag is an explicit opt-in; the package must still pass the module-structure validation.
- A new app refuses third-party versions younger than 5 days (`npmMinimalAgeGate: 5d` in `.yarnrc.yml`). The module page shows the date a fresh release becomes installable as **Installable from**. Until then the catalog keeps recommending the previous version.

See the [`module add` CLI reference](/cli/module-add) for multi-module packages, version selection, and ejection.

## What Listed and Verified mean

- **Listed**: the entry is valid, the npm package exists with a stable version and is not deprecated, the published package matches its kind (a module package contains `src/modules/<id>/` and `dist/modules/<id>/`; tools and libraries are listed too), the license is shown (or shown as unknown), and there is no known malware or open critical advisory. Checked by machine.
- **Verified** (for example `VERIFIED · 0.9`): within the last 14 days the catalog installed the newest installable stable version in a fresh app of the latest Open Mercato line, with a green baseline, and the app generated, built, and started. The package must also fit the latest line statically and pass the supply chain, hygiene, and source checks. Granted and removed automatically. The module page shows the install result on each line separately. A release that is still waiting for **Installable from** does not remove the level from the previous version.
- **OM Quality**: a human review against a published checklist. It requires Verified.

Neither level is a code review of the module. The rules are on the [quality page](https://modules.openmercato.com/quality).

## Eject a module {#ejecting-a-module}

If you need full control over a module's source code, eject it into your app:

```bash
yarn mercato module add @open-mercato/<module-name> --eject
```

The source is copied to `src/modules/<moduleId>/` and loaded locally. You can edit it freely; the framework treats it as an app-level module from that point on. See the [`eject` CLI reference](/cli/eject) for details.

## Enable an already-installed module {#enabling-an-already-installed-module}

If the package is already in `node_modules` (for example added as a dependency by another package), register it without reinstalling:

```bash
yarn mercato module enable @open-mercato/<module-name>
```

See the [`module enable` CLI reference](/cli/module-enable) for details.

## Publish and list your module {#publishing-your-module}

1. **Publish it.** [`create-mercato-module`](https://github.com/open-mercato/create-mercato-module) turns one module of your app into an npm package, optionally with its own GitHub repository. Follow [Publishing Custom Modules](/framework/modules/publishing-custom-modules).
2. **List it.** Open [modules.openmercato.com/submit](https://modules.openmercato.com/submit) and paste the npm package name (or open `https://modules.openmercato.com/submit?npm=<your-package>`). The page checks the package, its license, and the **Installable from** date, builds the catalog entry, and opens GitHub with the file filled in; commit it and open the pull request.

After the pull request is merged, the module is read from its published source within minutes and installed in the next nightly run. To request an OM Quality review, follow the steps on the [quality page](https://modules.openmercato.com/quality).

Contributors who still work on the legacy `official-modules` repository from inside this monorepo can find the git-submodule workflow in [Developing Official Modules](/framework/modules/official-modules-development).
