While the [CRUD factory](./crud-factory) covers most cases, sometimes you need bespoke endpoints—aggregations, external integrations, or webhooks. Follow these guidelines to extend module APIs safely.

## File structure

```
src/modules/<module>/api/<path>/route.ts
```

Example: `api/organizations/invite/route.ts` handles `/api/organizations/invite`.

Each file exports handlers for HTTP methods (GET, POST, PUT, DELETE, etc.) following Next.js App Router conventions.

```ts title="api/organizations/invite/route.ts"
import { NextResponse } from "next/server";
import { z } from "zod";
import { createRequestContainer } from "@/lib/di/container";
import type { AuthContext } from "@open-mercato/shared/lib/auth/server";

const inputSchema = z.object({
  email: z.string().email(),
  roleId: z.string().uuid(),
});

export async function POST(req: Request, { auth }: { auth: AuthContext }) {
  const body = inputSchema.parse(await req.json());

  const container = await createRequestContainer();
  const invitations = container.resolve("organizationInvitationService");

  await invitations.inviteUser({
    ...body,
    organizationId: auth.organizationId,
  });

  return NextResponse.json({ ok: true });
}

export const metadata = {
  POST: {
    requireAuth: true,
    requireFeatures: ["directory.invite"],
  },
};
```

## Best practices

- **Validate all inputs** using Zod schemas colocated with the entity or service they touch.
- **Respect tenant boundaries** by scoping queries to `organizationId` or `tenantId` from the request context.
- **Use services, not repositories directly** – resolve them from DI so you can unit test independently and override implementations per tenant.
- **Emit events deliberately** when downstream modules should react; otherwise keep handlers idempotent.
- **Document metadata** (`requireFeatures`, `requireRoles`) to integrate with admin navigation and ACLs.

## API interceptor route identity

The catch-all API dispatcher binds the matched manifest route to the request before
calling a handler. API interceptor selection consumes that identity: static segments
use the route's authored spelling, and dynamic/catch-all segments keep their matched
parameter values. Mixed-case and percent-encoded spellings that dispatch to the same
route therefore run the same exact and wildcard interceptors. Malformed path encoding
is rejected before handler execution.

Custom interceptor wrappers must use the dispatcher-bound request identity (the shared
CRUD factory does this automatically), or pass an authored route constant to the
interceptor runner. Do not derive a policy key independently from `request.url`; doing
so can make dispatch and policy matching disagree. This identity does not alter the
request URL, query string, or `ctx.params` received by the handler.

The identity survives `request.clone()` and `new Request(request.url, request)`.
Wrappers that reconstruct a request with an explicit `RequestInit` must retain the
original headers or pass an authored route constant to the interceptor runner. The
framework overwrites caller-supplied identity metadata at dispatch, bounds its
process-local continuity state, and rejects unknown or expired metadata rather than
falling back to the raw URL.

Mixing CRUD factories and bespoke endpoints gives you the flexibility to move fast while keeping the platform predictable.

## Dispatcher tenant-extraction body-peek budget

Before a route handler runs, the dispatcher peeks at the request body for a
`tenantId` field so it can enforce tenant selection (#2665) against every
candidate the request carries — query string and body alike — ahead of the
handler's own, larger body parsing. That peek is capped by
`OM_API_TENANT_EXTRACT_MAX_BYTES` (default 64 KB) so an authenticated caller
can't force a full JSON/multipart body to be buffered just to extract one
field (#7811).

A non-superadmin request whose body exceeds this budget is now **rejected
with 403**, not silently let through: the dispatcher cannot verify there is
no foreign `tenantId` hiding past the peek limit, and fails closed rather
than treating the unknown as "no candidate" (#7877). This affects any
authenticated, non-superadmin write whose body — including attachments,
bulk imports, or other large payloads — exceeds 64 KB and whose route still
expects the dispatcher to read a body-level `tenantId`. Operators whose
routes legitimately send larger authenticated bodies should raise
`OM_API_TENANT_EXTRACT_MAX_BYTES` accordingly; superadmin callers are
unaffected, since they may already select any tenant.
