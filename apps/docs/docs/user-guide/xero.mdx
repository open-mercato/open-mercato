# Xero

The Xero integration connects one Xero Organisation to each Open Mercato organization and imports its Contacts into **Companies** every hour. A Contact always updates the same Company, so repeated runs never create duplicates.

- **Import only.** Open Mercato reads Contacts from Xero and never writes back.
- **Xero owns the fields it sends.** Name, legal name, email, phone, website, status, tax number and the Xero addresses are overwritten from Xero on the next run that returns the Contact. Every other Company field, note and activity stays yours.
- **Grants are per organization.** Each Open Mercato organization connects its own Xero Organisation through OAuth2. Tokens are encrypted and never shown.

## Before you start

- **`APP_URL`** is the base of the redirect URI. Production needs an `https` URL; for local testing use `http://localhost:<port>`. Xero rejects `127.0.0.1`.
- **`OM_HUB_OAUTH_STATE_KEY`** (or `KMS_MASTER_KEY`) must be set in production. Connect fails without it.
- **`CACHE_STRATEGY=redis`** when more than one web replica serves the app, so each Connect state is used only once.
- The **scheduler** module runs the hourly schedule. Without it, Contacts sync only when started by hand.
- You need `integrations.credentials.manage` to connect, choose an Organisation and disconnect.

## 1. Register a Xero app

1. Sign in at [developer.xero.com](https://developer.xero.com) and open **My Apps → New app**.
2. Choose **Web app**.
3. Enter the redirect URI shown on the **Xero** tab of the integration (Integrations → Xero → Xero). It is `<APP_URL>/api/sync_xero/oauth/callback`, for example `https://app.example.com/api/sync_xero/oauth/callback`. It must match exactly.
4. Create the app, copy its **Client ID** and generate a **Client Secret**.

One Xero app can serve every organization of your Open Mercato instance: each organization connects with its own consent.

## 2. Enter the Client ID and Secret

Open **Integrations → Xero → Credentials**, enter the Client ID and Client Secret, and save.

## 3. Connect a Xero Organisation

1. Open the **Xero** tab and click **Connect**.
2. Sign in to Xero, review the requested access and choose the Organisation to allow.
3. Back in Open Mercato, the tab shows the connected Organisation. When the consent covered several Organisations, choose one on the tab.

Open Mercato requests read-only access to Contacts and Invoices (`accounting.contacts.read`, `accounting.invoices.read`) plus `offline_access`, which keeps the connection alive between runs. Invoices are reserved for a later release; Xero cannot add a scope to an existing connection without a new consent, so it is requested now.

### Try it with the Xero Demo Company

Every Xero login has a **Demo Company** with sample contacts and invoices. Register the app with `APP_URL=http://localhost:3000` (or your local port), connect, and choose the Demo Company in Xero's consent screen. Nothing you do there touches real financial data.

## Daily limits

Xero limits each Organisation to 60 calls a minute and to a daily number of calls set by your Xero app's pricing tier: **1,000 a day** for a new app (Starter tier) and 5,000 on Core. One run reads up to 1,000 Contacts per call, so an hourly sync of a typical Organisation uses a few dozen calls a day. When the daily limit is reached, the run stops quietly and the next run continues where it left off.

## Disconnect

**Disconnect** on the Xero tab erases the stored tokens and asks Xero to revoke them.

:::warning Revocation reaches every connection of the same Xero user
Xero ends **every** connection that the same Xero user authorized for the same Xero app, not only this one. If one Xero user connected several Open Mercato organizations through one Xero app, Disconnect ends all of them; each must connect again.
:::

When Xero cannot confirm the revocation, remove the app from the Organisation's **Connected apps** in Xero.
