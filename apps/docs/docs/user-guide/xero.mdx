# Xero

The Xero integration connects one Xero Organisation to each Open Mercato organization and imports its Contacts into **Companies** every hour. A Contact always updates the same Company, so repeated runs never create duplicates.

- **Import only.** Open Mercato reads Contacts from Xero and never writes back.
- **Xero owns the fields it sends.** Name, legal name, email, phone, website, archive status, tax number and the Xero addresses are overwritten from Xero on the next run that returns the Contact. Every other Company field, note and activity stays yours.
- **Not every Contact becomes a Company.** A Contact that has no Company yet is skipped when it is only a supplier, archived or redacted for GDPR.
- **Grants are per organization.** Each Open Mercato organization connects its own Xero Organisation through OAuth2. Tokens are encrypted and never shown.

## Before you start

- **`APP_URL`** is the base of the redirect URI. Production needs an `https` URL; for local testing use `http://localhost:<port>`. Xero rejects `127.0.0.1`.
- **`OM_HUB_OAUTH_STATE_KEY`** (or `KMS_MASTER_KEY`) must be set in production. Connect fails without it.
- **`CACHE_STRATEGY=redis`** when more than one web replica serves the app, so each Connect state is used only once.
- The **scheduler** module runs the hourly schedule. Without it, Contacts sync only when started by hand.
- You need `integrations.credentials.manage` to connect, choose an Organisation and disconnect, and `integrations.manage` to enable the integration.

## 1. Register a Xero app

1. Sign in at [developer.xero.com](https://developer.xero.com) and open **My Apps → New app**.
2. Choose **Web app**.
3. Enter the redirect URI shown on the **Xero** tab of the integration (Integrations → Xero → Xero). It is `<APP_URL>/api/sync_xero/oauth/callback`, for example `https://app.example.com/api/sync_xero/oauth/callback`. It must match exactly.
4. Create the app, copy its **Client ID** and generate a **Client Secret**.

Register one Xero app per Open Mercato organization. Disconnect ends every connection the same Xero user authorized for the same app, so a shared app ties those organizations together (see [Disconnect](#disconnect)).

## 2. Enter the Client ID and Secret

Open **Integrations → Xero → Credentials**, enter the Client ID and Client Secret, and save.

## 3. Connect a Xero Organisation

1. Open the **Xero** tab and click **Connect**.
2. Sign in to Xero, review the requested access and choose the Organisation to allow.
3. Back in Open Mercato, the tab shows the connected Organisation. When the consent covered several Organisations, choose one on the tab.

Open Mercato requests read-only access to Contacts and Invoices (`accounting.contacts.read`, `accounting.invoices.read`) plus `offline_access`, which keeps the connection alive between runs. Invoices are reserved for a later release; Xero cannot add a scope to an existing connection without a new consent, so it is requested now.

### Try it with the Xero Demo Company

Every Xero login has a **Demo Company** with sample contacts and invoices. Register the app with `APP_URL=http://localhost:3000` (or your local port), connect, and choose the Demo Company in Xero's consent screen. Do this in a separate Open Mercato organization, so the sample contacts stay out of your real Companies. Nothing you do there touches real financial data.

## 4. Enable the integration

The integration starts disabled: the Xero tab shows a paused warning and no scheduled run fires. A first sync matches a Contact to an existing Company by tax number, so prepare any Companies you already have before you enable it:

1. Connect while the integration is still disabled. The **Tax number (Xero)** custom field exists from the moment the Organisation is saved.
2. Fill in **Tax number (Xero)** on the Companies you entered by hand, with the number Xero holds as the Contact's Tax Number or Company Number.
3. Turn on the **State** switch on the integration's detail page.

A Company without that number is not matched: its Contact creates a new Company, and the run log warns when the names are the same.

## Schedules and Xero's 60-day limit

When the Organisation is saved, Open Mercato creates an hourly incremental schedule for Contacts, unless one exists already, also for a user without `data_sync.configure`: the schedule is what keeps the Xero connection alive. An existing schedule is never changed, and a `data_sync.schedule` mutation guard can still block the creation or change the new schedule, for example create it disabled; a guard change to the integration, entity type or direction refuses the creation. Enable the integration to let it run. The Xero tab lists the schedule and offers **Create default schedule** when it is missing; that button needs `data_sync.configure`.

Xero ends a connection that is not used for 60 days. Every sync renews it, so an enabled integration with its schedule never reaches the limit. When syncing is paused or no schedule is enabled, the Xero tab shows how many days are left before Xero requires a Reconnect.

Keep **Run scheduled jobs as full sync** off: a full sync reads every contact on each run and cannot resume a run that Xero's daily limit interrupts. To re-read everything once, start a single run with **Run as full sync** from **Sync Runs**. Do this after failed items, and when a supplier becomes a customer in Xero: hourly runs read only the Contacts Xero reports as changed, and Xero does not report that change.

## Daily limits

Xero limits each Organisation to 60 calls a minute and to a daily number of calls set by your Xero app's pricing tier: **1,000 a day** for a new app (Starter tier) and 5,000 on Core. One run reads up to 1,000 Contacts per call, so an hourly sync of a typical Organisation uses a few dozen calls a day. When the daily limit is reached, the run stops quietly and the next run continues where it left off.

## Disconnect

**Disconnect** on the Xero tab erases the stored tokens and asks Xero to revoke them. Then it runs one health check and disables the integration, so the schedules stop firing; they resume when you reconnect and enable the integration again. Disabling needs `integrations.manage`: without it the integration stays enabled, the tab says so, and an administrator must disable it. Companies imported so far stay. Tick **Also remove the Client ID and Secret** to clear the Credentials tab as well.

When the stored connection cannot be read (for example after an encryption key change), the tab offers **Replace unreadable connection**, which connects again over it, and **Disconnect anyway**, which erases it without a revoke. After **Disconnect anyway**, remove the app from the Organisation's **Connected apps** in Xero yourself. After a replace, remove it only if you no longer use it: removing it ends the new connection too.

:::warning Revocation reaches every connection of the same Xero user
Xero ends **every** connection that the same Xero user authorized for the same Xero app, not only this one. If one Xero user connected several Open Mercato organizations through one Xero app, Disconnect ends all of them; each must connect again.
:::

When Xero cannot confirm the revocation, remove the app from the Organisation's **Connected apps** in Xero.
