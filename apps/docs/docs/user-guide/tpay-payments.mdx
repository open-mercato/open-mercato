This guide explains how to connect Tpay to Open Mercato and accept PLN payments through Tpay's hosted payment page. The payer is redirected to Tpay, chooses a payment method there (online transfer, BLIK, and other methods enabled on your Tpay account), and returns to your checkout page.

## Before you start

- A Tpay merchant account. For testing, create a sandbox account in the Tpay sandbox panel.
- An Open API key from **Tpay Merchant Panel → Integrations → API** (Client ID and Secret).
- The `gateway_tpay` module enabled in your application's `modules.ts`.
- The `integrations.credentials.manage` and `payment_gateways.manage` features enabled for your role.

## Configure the integration

1. Navigate to **External Systems → Integrations** and click **Configure** on the Tpay card.
2. Fill in the credentials:
   - **Client ID** and **Client Secret** — from the Tpay API key.
   - **Environment** — `Sandbox` for sandbox credentials, `Production` for live credentials. Open Mercato uses Tpay's fixed sandbox or production API address for the selected environment.
   - **Notification URL** (optional) — the public HTTPS address Tpay will notify about payment results. It must not contain credentials, a query string, or a fragment, and production requires port 443. Leave it empty if the Tpay Merchant Panel already defines the notification address.
   - **Notification Security Code** — the security code from **Tpay Merchant Panel → Settings → Notifications → Security**. Required for payment notifications; without it every notification is rejected.
3. Save and run the health check. A healthy result means Open Mercato obtained an access token from Tpay with these credentials.
4. Enable the integration.

## Optional env preconfiguration

```env
OM_INTEGRATION_TPAY_CLIENT_ID=...
OM_INTEGRATION_TPAY_CLIENT_SECRET=...
OM_INTEGRATION_TPAY_ENVIRONMENT=sandbox
OM_INTEGRATION_TPAY_NOTIFICATION_URL=
OM_INTEGRATION_TPAY_NOTIFICATION_SECURITY_CODE=
OM_INTEGRATION_TPAY_ENABLED=true
OM_INTEGRATION_TPAY_FORCE_PRECONFIGURE=false
```

Client ID and Client Secret are required together. In standalone apps created with `create-mercato-app`, the module is opt-in: uncomment `gateway_tpay` in `src/modules.ts`. New tenants pick the preset up automatically. To apply it to an existing tenant:

```bash
yarn mercato gateway_tpay configure-from-env --tenant <tenantId> --org <organizationId> [--force]
```

Without `--force`, existing Tpay credentials or integration state are left untouched.

## Using Tpay in checkout

Select **Tpay** as the payment provider of a checkout link and keep customer details collection enabled: Tpay requires the payer's email address and name, and checkout forwards the values the payer enters. Payments without an email address or name are rejected before anything is sent to Tpay.

After paying, the payer returns to the checkout success page, which reads the transaction status from Tpay. A paid transaction becomes **captured**.

## Payment notifications

Tpay confirms each paid transaction with a server-to-server notification. Open Mercato settles the payment from that notification, so a payment is captured even when the payer closes the browser on Tpay's page.

1. In the Tpay Merchant Panel, set the notification address to `https://<your-domain>/api/payment_gateways/webhook/tpay` (or fill **Notification URL** in the integration, which Tpay uses when overriding is allowed). The address must be public HTTPS on port 443, without redirects.
2. Copy the notification security code (Tpay Merchant Panel → Settings → Notifications → Security) into **Notification Security Code**. Without it every notification is rejected and the integration health check reports a degraded status.
3. Save the integration.

Each notification is checked before anything changes:

- the MD5 checksum built with your security code;
- Tpay's JWS signature, using Tpay's production or sandbox certificate according to the integration **Environment**;
- the transaction it refers to (`tr_crc` is the payment id Open Mercato sent to Tpay), its amount, and its currency.

| Situation | Response to Tpay | Effect |
| --- | --- | --- |
| Verified and processed | `200 TRUE` | Payment captured (or refunded for a chargeback) once, even if Tpay repeats the notification |
| Transaction not found yet, certificate download or validation failed, or processing failed | `503 FALSE` | Tpay retries later |
| Invalid checksum or signature, amount/currency mismatch, underpayment | `400 FALSE` | Nothing changes; Tpay keeps retrying — check the security code and the integration environment |

An overpayment still captures the expected amount; the paid amount is kept in the transaction details.

## Scheduled status check

When the Tpay integration is enabled for an organization, Open Mercato registers a scheduled job (**Tpay payment status reconciliation**, every 5 minutes) that asks Tpay for the current status of that organization's Tpay transactions that are still open (pending, authorized, or partially captured). It repairs payments whose notification never arrived, for example because the notification address was misconfigured or Tpay exhausted its retries.

- The job is created or re-enabled when you enable the integration and disabled when you disable it. You can also pause it in the scheduler.
- Each run checks the 100 open transactions (pending, authorized, or partially captured) that have gone longest without a change. If more than 100 open transactions never change, they can keep newer ones from being checked; Tpay's panel and the return-page check still apply to those payments.
- It needs the scheduler module. Without it, notifications and the return-page check still work.

## Limitations

- **PLN only.** Sessions in any other currency are rejected.
- **One Tpay transaction per payment.** If a payment was retried and Tpay holds several transactions with the same amount for it, notifications cannot tell them apart and are rejected; the scheduled status check settles such payments instead (within about 5 minutes).
- **No refunds, cancellation, or manual capture** from Open Mercato. Use the Tpay Merchant Panel for these operations.
