# perf/ internal contracts

Shared interfaces between the seeder (`mercato customers seed-perf`), the k6 scripts, and the
orchestration scripts. Spec: `.ai/specs/2026-11-26-crm-performance-test-plan.md`. Change a contract
here first, then every consumer.

## Compose stack

| Item | Value |
|---|---|
| Compose project | `COMPOSE_PROJECT_NAME=om-perf` |
| `DEPLOY_ENV` | `perf`. Container names follow it: `mercato-postgres-perf`, `mercato-redis-perf`, `mercato-meilisearch-perf`, `mercato-app-…` (the service is `app`) |
| Docker network | `mercato-network-perf-v2` |
| Compose files, in order | `docker-compose.fullapp.yml`, `perf/sut/compose.perf.yml`, `perf/monitoring/compose.monitoring.yml` |
| Env file | `perf/config/sut.local.env`. It is gitignored and generated by `perf/bin/perf init-secrets` from `perf/config/sut.example.env` |
| Services added by `perf/sut/compose.perf.yml` | `worker` (runs `yarn mercato queue worker --all`), `scheduler` (runs `yarn mercato scheduler start`), `tls` (Caddy reverse proxy `https://:8443` → `app:3000`, `tls internal` by default, or a real domain via `PERF_TLS_DOMAIN`), `mailpit` (SMTP sink) |
| Services moved to an unused profile (`perf-disabled`) | `opencode`, `mcp`, `documents-collab` |
| Services added by `perf/monitoring/compose.monitoring.yml` | `prometheus` (with `--web.enable-remote-write-receiver`), `grafana`, `node-exporter`, `cadvisor`, `postgres-exporter`, `redis-exporter`. The stock `otel-collector` is enabled and its config overridden |

Default database name: `open-mercato`. A snapshot template is named `perf_<tier>_template`, with `tier` in lower case.

## Target config: `perf/config/target.local.env` (gitignored)

```
PERF_TARGET_NAME=local            # free-form label recorded in run.json
PERF_TARGET_KIND=local            # local | vps
BASE_URL=https://tls:8443         # URL k6 uses (inside the generator container)
SUT_SSH=                          # empty = local docker; otherwise user@host for SUT-side commands
SUT_REPO_DIR=                     # repo checkout path on the SUT (vps only)
GENERATOR_LOCATION=laptop-local   # recorded in run.json; comparability key
HARDWARE_PROFILE=local-mac        # key into perf/config/hardware.md; comparability key
K6_NETWORK=mercato-network-perf-v2  # docker network for the k6 container when local; empty on vps
PROM_RW_URL=http://prometheus:9090/api/v1/write   # vps: http://127.0.0.1:19090/... through ssh -L
```

## State: `perf/.state/` (gitignored, mode 700)

| File | Shape |
|---|---|

| `background-tenants.json` | `[{ "tenantId", "organizationId" }]` |

## Seeder: `mercato customers seed-perf`

```
yarn mercato customers seed-perf --tenant <id> --org <id> --tier S|M|L|XS
  [--profile perf-v1] [--seed 42] [--anchor YYYY-MM-DD] --owners-file <path>
  [--batch 1000] [--resume] [--out-dir <dir>] [--dry-run] [--scale <float>]
```

- `XS` is a 2,000-entity tier for unit, integration and smoke checks. `--scale` multiplies a tier's entity count (it is how background tenants get 5%).
- Output goes to `<out-dir>` (default `./.mercato/perf-seed/<tier>`): `manifest.json` and `catalog.json`. The orchestration copies them to `perf/data/<tier>/`.
- Exit codes: `0` success, `2` usage error, `3` verification failed, `4` resumable failure.
- It does **not** run reindexing. `perf/bin/perf seed` does that afterwards.

### `manifest.json`

```json
{
  "version": 1, "profile": "perf-v1", "tier": "S", "seed": 42, "anchor": "2026-11-26",
  "tenantId": "…", "organizationId": "…",
  "counts": { "customer_entities": 0, "customer_people": 0, "customer_companies": 0,
              "customer_interactions": 0, "customer_deals": 0, "customer_deal_people": 0,
              "customer_deal_companies": 0, "customer_deal_stage_transitions": 0,
              "customer_comments": 0, "customer_addresses": 0, "customer_tags": 0,
              "customer_tag_assignments": 0, "customer_person_company_links": 0,
              "custom_field_values": 0 },
  "checksum": "sha256 of the canonical JSON of {profile,tier,seed,anchor,counts}",
  "startedAt": "…", "finishedAt": "…", "durationMs": 0
}
```

### `catalog.json`

Ids only, plus plaintext terms. Every array is capped at 2,000 entries.

```json
{
  "version": 1, "profile": "perf-v1", "tier": "S", "seed": 42, "anchor": "2026-11-26",
  "tenantId": "…", "organizationId": "…",
  "people":    { "light": [], "medium": [], "heavy": [], "extreme": [] },
  "companies": { "light": [], "medium": [], "heavy": [], "extreme": [] },
  "hotSet":    { "people": [], "companies": [] },
  "pipelines": [{ "id": "…", "name": "…", "stages": [{ "id": "…", "name": "…", "order": 0 }] }],
  "deals":     { "sample": [], "byStage": { "<stageId>": [] } },
  "tags": [],
  "owners": [], "heavyOwners": [],
  "searchTerms": {
    "unique": [{ "term": "…", "expected": 1 }],
    "common": [{ "term": "…", "expected": 0 }],
    "prefix": [{ "term": "…", "expected": 0 }],
    "noHit":  [{ "term": "…", "expected": 0 }]
  },
  "emailPrefixes": [],
  "dictionaries": { "statuses": [], "lifecycleStages": [], "sources": [] }
}
```

Buckets are defined by interaction count per entity: `light` 1–5, `medium` 6–20, `heavy` 21–100,
`extreme` more than 100. `hotSet` holds 50 people and 20 companies that 10% of writes edit
concurrently.

## k6

The k6 image is pinned in `perf/generator/compose.generator.yml`. Inside the container:

- `/perf` is the repo's `perf/` directory, read-only.
- `/perf/.state/users.json` and `/perf/data/<tier>/catalog.json` are mounted.
- `/out` is the run folder (`perf/results/<run-id>/raw`).

Environment variables passed to k6:

```
BASE_URL, TIER, CATALOG=/perf/data/<tier>/catalog.json, USERS=/perf/.state/users.json,
WORKLOAD=/perf/config/workload.json, PROFILE=<step|stress|soak|mini|...>, RUN_ID, PHASE,
INSECURE_TLS=1, K6_PROMETHEUS_RW_SERVER_URL, K6_PROMETHEUS_RW_TREND_STATS=p(50),p(95),p(99),max
SUMMARY_OUT=/out/summary.json
```

Scenario files live in `perf/k6/scenarios/`: `smoke.js`, `baseline.js`, `mixed.js` (with `PROFILE`), `interference.js`, `browser.js`.
Each one writes `summary.json` from `handleSummary`.

Metric tags: `group` (`read` | `write` | `heavy` | `shell` | `auth`), `journey`, `name` (the endpoint tag from the
spec's API table, e.g. `people.list:list`), `phase`, `step` (the load step index). Custom metrics:
- `om_conflicts` (Counter, 409 optimistic lock),
- `om_journey_duration` (Trend, tag `journey`),
- `om_bulk_job_duration` (Trend).

## Run folder: `perf/results/<YYYY-MM-DD>-<tier>-<scenario>-<label>/`

- `run.json` and `report.md` are committed.
- `raw/` (k6 summary, logs, pg snapshots, Prometheus exports) is gitignored.

`run.json` fields: `runId`, `scenario`, `profile`, `tier`, `gitSha`, `imageDigest`, `modules[]`,
`envHash`, `envNotable{}`, `hardwareProfile`, `generatorLocation`, `rtt{p50,p95}`, `k6Version`,
`migrationHead`, `datasetAnchor`, `datasetAgeDays`, `snapshotId`, `startedAt`, `finishedAt`, `params{}`,
`localValidation` (boolean).

## workload.json

`perf/config/workload.json` is the single source of the load shape. k6 reads it through `WORKLOAD`
and deep-merges it over the defaults in `perf/k6/lib/pure/workload.js`; the orchestration reads
`saturation`, `reference` and `generatorLimits` for the report. Durations are k6 strings (`30s`, `2m`, `4h`).
Shares and weights are relative numbers (they need not sum to 100).

| Key | Shape | Meaning |
|---|---|---|
| `version`, `name` | `1`, `"perf-v1"` | Changing the mix needs a new `name`; never edit `perf-v1` in place once a round used it |
| `groups.<read\|write\|heavy>` | `{ share, journeys: { <journeyId>: weight } }` | Group share of protocol iterations, journey weights inside the group |
| `thinkTime` | `{ minSeconds, maxSeconds }` | Seeded uniform think time between page actions |
| `sampling` | `{ buckets: { lightMedium, heavy, extreme }, hotSetWriteShare, recentShare }` | Entity bucket mix for 360 journeys; share of writes on the hot set; share of reads on records created during the run |
| `warmup` | `{ vus, duration }` | Prepended to every load profile; samples carry tag `step=warmup` and are excluded from statistics |
| `bulk` | `{ mixedSize, interferenceSize }` | Deals per bulk job in mixed load (fire-and-forget) and in the interference injector (polled) |
| `login` | `{ ratePerMinute }` | Pace of the separate login-measurement scenario |
| `profiles.mini`, `profiles.step` | `{ kind: "steps", ramp, hold, steps: [vus…] }` | Ramp to each VU level, then hold |
| `profiles.stress` | `{ kind: "stress", ramp, hold, multipliers[], fallbackVus[], recovery: { vus, ramp, hold } }` | Multipliers of `KNEE_VUS`; `fallbackVus` when no knee was found |
| `profiles.soak` | `{ kind: "soak", fraction, fallbackVus, ramp, hold }` | `fraction × KNEE_VUS` held for `hold` |
| `interference` | `{ vus, kneeFraction, controlWindow, injectionWindow, recoveryWindow, injectorRatePerMinute, injectorJourneys[], bulkOffsets[], bulkPollIntervalSeconds, bulkTimeout }` | Phase 7: mixed load without the heavy group plus a `constant-arrival-rate` injector |
| `smoke` | `{ vus, duration, thinkTime }` | Phase 4 |
| `baseline` | `{ samples, warmupRounds }` | Phase 5; `SAMPLES` overrides `samples` |
| `browser` | `{ vus, maxVus, duration }` | k6 browser VUs running alongside protocol load |
| `safety` | `{ maxErrorRate, errorWindow, maxP95Ms }` | The only conditions that abort a run |
| `reference` | `{ readP95Ms, errorRate, lcpMs, inpMs, cls }` | Non-failing reference lines in the report |
| `saturation` | `{ p95Factor, maxErrorRate, minThroughputGrowthRatio }` | Knee criteria applied by `report.mjs` against the first measured step |
| `generatorLimits` | `{ maxCpuShare, maxDroppedIterations }` | A step over these is marked invalid in the report |

## Orchestration additions

Target keys beyond the list above (all in `target.example.env`):

```
CONTROL_BASE_URL=https://localhost:8443   # URL perf/bin/perf itself calls (users, reindex, checks)
CALIBRATE_URL=                            # calibration target, default CONTROL_BASE_URL
PROM_QUERY_URL=http://127.0.0.1:9090      # Prometheus HTTP API for report.mjs (vps: the ssh tunnel)
INSECURE_TLS=1                            # accept the self-signed Caddy certificate
```

Extra k6 environment set by `perf/bin/perf run`: `SAMPLES` (baseline, from `--samples`),
`KNEE_VUS` (stress, soak, interference, from `--knee`), `LABEL`. Every k6 run also gets
`--tag run_id=<RUN_ID>` and two outputs: `experimental-prometheus-rw` and `csv=/out/metrics.csv.gz`.
`report.mjs` computes per-tag statistics from the CSV (tags `name`, `group`, `journey`, `step`,
`phase` as columns or in `extra_tags`), and falls back to `summary.json` submetrics when the CSV is
missing. Rows tagged `step=warmup` are excluded.

The run folder additionally holds `report.json` (aggregated statistics, no secrets, committed),
which `compare.mjs` reads. `perf/.state/` also holds `target-ack.json` (first-use confirmation of the
target), `seed-<tier>.json` (seed + reindex + verification result; `snapshot` requires `verified: true`)
and `snapshots/<tier>.keys.env` (mode 600, the encryption keys the snapshot was seeded with).
