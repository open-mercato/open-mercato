# Integrity and Concurrency

Load this reference for writes, locking, retries, and relation synchronization.

- Dispatch domain writes through commands. Capture before/after state needed by audit and undo. In `undo`, read the stored payload with `extractUndoPayload` from `@open-mercato/shared/lib/commands/undo`, re-authorize and re-scope the reversal, make retries safe, and restore the matching cache/event/index aliases. Never ship an empty or stub `undo`; create/update/delete each reverse their persisted mutation. For custom fields you must call `buildCustomFieldResetMap` from `@open-mercato/shared/lib/commands/customFieldSnapshots`, compare the captured before/after maps, and persist its reset map on update/delete undo; `Object.assign` alone does not replace the reset-map call because cleared/removed keys also need restoration.
- Capture custom fields with `loadCustomFieldSnapshot(em, { entityId, recordId, tenantId, organizationId })` from that same `commands/customFieldSnapshots` module. `DataEngine` has no `getCustomFields`; write them only with the single object argument `dataEngine.setCustomFields({ entityId, recordId, tenantId, organizationId, values, notify })`, never positional arguments.
- Type each object as `CommandHandler<Input, Result>`, implement `undo: async ({ logEntry, ctx }) => { ... }`, then call `registerCommand(command)` separately; `registerCommand` returns no command object. Call `extractUndoPayload<UndoPayload>(logEntry)`. Enforce a lock with the single options object `enforceCommandOptimisticLock({ resourceKind, resourceId, current, expected, request: ctx.request })`, not positional timestamps.
- `execute` returns `Result` directly, never `{ result, undo }`. `prepare` returns exactly `{ before: snapshot }`; `captureAfter` returns the after-snapshot value directly; `buildLog({ result, snapshots, ctx })` reads `snapshots.before`/`snapshots.after` and returns `{ resourceId: result.id, payload: { undo: ... } }`. Never invent `snapshots.snapshot` or nest payload under `{ metadata: { payload } }`, and never cast or mutate `ctx` to shuttle command-local undo state. The command bus supplies that log to `undo`. Guard a nullable `extractUndoPayload` result before reading it. `logEntry.resourceId` is nullable, so store the stable record ID in the undo payload and validate/use that required string (or explicitly guard `resourceId`) before a scoped finder call.
- Resolve infrastructure with types: `const em = ctx.container.resolve<EntityManager>('em').fork()` and `const dataEngine = ctx.container.resolve<DataEngine>('dataEngine')`, importing `CommandRuntimeContext`, `EntityManager` from `@mikro-orm/postgresql`, and `DataEngine` from `@open-mercato/shared/lib/data/engine`. Type command helpers as `(ctx: CommandRuntimeContext)`; do not cast `ctx` or `ctx.container` to `any` and then apply generic type arguments. Trusted scope is `ctx.auth?.tenantId` plus the concrete string `ctx.selectedOrganizationId ?? ctx.organizationScope?.selectedId`; `ctx.organizationScope` is an object, never an organization ID. `ctx.auth.organizationId`, `ctx.em`, and `ctx.dataEngine` are not command runtime fields.
- Import `withAtomicFlush` from `@open-mercato/shared/lib/commands/flush` and call `withAtomicFlush(em, [() => { em.persist(record) }, async () => { await syncRelations() }], { transaction: true })`: the second argument is an array of zero-argument phases that close over the same `EntityManager`, not one callback receiving an `em`. A phase callback must return `void`/`Promise<void>`; use a block such as `() => { em.persist(record) }`, never the expression `() => em.persist(record)` that returns the manager. Keep notifications, queues, external calls, cache invalidation, and indexing after commit, with durable compensation/recovery when those side effects can fail. Import `emitCrudSideEffects`/`emitCrudUndoSideEffects` from `@open-mercato/shared/lib/commands/helpers` and pass their documented options object (`dataEngine`, action, entity, scoped identifiers, events/indexer), not a runtime context plus invented effects descriptor.
- MikroORM `em.create(Entity, data)` must receive all required typed fields even when entity property initializers exist: supply `created_at` and `updated_at` on create (or the entity's camel-case equivalents). Delete undo must capture a concrete full snapshot and rebuild every required field explicitly; do not pass `Partial<Entity>` to `em.create`.
- CRUD effects use past-tense `action: 'created' | 'updated' | 'deleted'` and `identifiers: { id, tenantId, organizationId }`. Define mutable typed values (`const events: CrudEventsConfig = ...`, `const indexer: CrudIndexerConfig = ...`) as `{ module, entity, persistent?, buildPayload? }` and `{ entityType, cacheAliases? }`; do not use `as const` for mutable `cacheAliases`, or put `eventId`/loose scope fields in an effect call.
- Give every external/queued retry a stable idempotency key and scoped uniqueness boundary.
- Return `updatedAt` for editable records. Let `CrudForm` send the version; custom clients build the lock header and surface 409 conflicts.
- Guard custom action/sub-resource writes at command level, normally against the aggregate parent version, with `enforceCommandOptimisticLock` from `@open-mercato/shared/lib/crud/optimistic-lock-command` (or its documented injectable guard service).
- If a parent form mutates children, send each child's own version.
- Persist external cursor/mapping/progress state only after the batch commits; never mark forward progress on transient failure.

Tests must inject rollback between phases, race two updates, retry one operation twice, clear a nullable value, and verify side effects occur exactly after commit.
