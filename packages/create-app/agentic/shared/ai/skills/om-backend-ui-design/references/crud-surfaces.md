# CRUD UI Surfaces

Load this reference for list/detail/create/edit/delete work.

Unless the brief explicitly excludes an operation, a new editable entity includes list, create, view/edit, and delete. The list supplies filter/search, a localized add action, and a linked row action; the forms use the shared CRUD helpers and return to a reachable list.

- DataTable: import `DataTable` from `@open-mercato/ui/backend/DataTable` and `RowActions` from `@open-mercato/ui/backend/RowActions` (not a backend barrel). Use `entityId="module:entity"` or `entityIds={['module:entity']}` (the latter is always an array) and `extensionTableId`; type the table generic so `rowActions` does not receive `unknown`. Load and pass `data`/pagination explicitly through the shared API helper—`DataTable` has no `apiPath` prop. The DataTable loading prop is `isLoading`, never `loading`. Pass controlled paging as `pagination={{ page, pageSize, total, totalPages, onPageChange, onPageSizeChange }}`, not top-level pagination props. Use controlled `searchValue`/`onSearchChange` and filter state passed to the server; complete pagination ownership; built-in empty/loading/error/export behavior. Put the localized add link to the canonical `/create` child route in `actions`. `emptyState` is a React node, not a `{ title, description }` object. `rowActions` renders `<RowActions items={[{ id: 'edit', label, href }, { id: 'delete', label, destructive: true, onSelect }]} />`; stable qualified IDs such as `module.resource.edit`/`.delete` are also valid. `RowActionItem` has no `requiredFeatures` field, so backend ACL remains authoritative and callers conditionally include actions when UI capability state is available. When authoring a new host UI, publish intentional extension spots with stable column, action, and row-action IDs rather than creating an isolated local-only table.
- CrudForm: import `CrudForm` and type `CrudField` from `@open-mercato/ui/backend/CrudForm`—never `CrudFormField`—plus `useT` from `@open-mercato/shared/lib/i18n/context`, API reads from `@open-mercato/ui/backend/utils/apiCall`, and create/update/delete from `@open-mercato/ui/backend/utils/crud`; CRUD helper paths omit the `/api/` prefix. Declare fields as `const fields: CrudField[]`; `CrudField` is not generic, although `<CrudForm<Values>>` is. `apiCall`/`apiCallOrThrow` return an `ApiCallResult`; use `readApiResultOrThrow<T>` when the caller needs the parsed payload directly. Use typed fields/groups, `injectionSpotId="crud-form:<module>.<resource>"`, shared helpers, `initialValues.updatedAt`, explicit null clearing, and translation keys. CrudForm has no `mapServerError` prop: it already catches errors thrown by `onSubmit`/`onDelete` and applies `mapCrudServerErrorToFormErrors` internally; import that helper only for a custom form outside CrudForm. CrudForm has no `onCancel` prop; use `cancelHref` for list navigation. A built-in field uses `id` as its form key and has neither `name` nor `clearable`; preserve/submit `null` explicitly for optional fields. `onSubmit` awaits the CRUD helper and returns `void`; `onDelete` receives no values argument, so capture the loaded record/`initialValues.updatedAt`, await `deleteCrud`, and return `void`. Call `collectCustomFieldValues(values, { transform? })` from `@open-mercato/ui/backend/utils/customFieldValues`; its second argument is an options object, never an entity ID. `deleteCrud(path, { id, body: { id, updatedAt } })` carries a version because `updatedAt` is not a top-level delete option.
- After a nullable loading guard, assign the loaded state to a non-null local such as `const initialValues = values` and use that local in nested submit/delete callbacks; TypeScript does not retain state-property narrowing across those closures. For destructive confirmation, use `const { confirm, ConfirmDialogElement } = useConfirmDialog()`, call `await confirm(...)`, and render `{ConfirmDialogElement}` in the returned tree; the hook result itself is not callable.
- Detail: load through shared API helpers, preserve scoped/auth errors, use reusable detail sections and stable extension spots. Keep host IDs aligned with the API `enrichers` entity ID and add widget/injection round-trip coverage when the surface is extensible.
- For detail loading, call `readApiResultOrThrow<T>(url)` directly and handle its `T | null` result; do not chain `apiCallOrThrow` as a `.then` callback. Use existing `Page`/`PageBody`, `Spinner` from `@open-mercato/ui/primitives/spinner`, and `Alert` from `@open-mercato/ui/primitives/alert`; do not invent `LoadingMessage` or `ErrorMessage` modules.
- Custom mutations: scoped API headers plus record-specific optimistic lock, shared conflict surfacing, duplicate-submit prevention.
- Injected fields: render/input + read/enricher + `collectCustomFieldValues` save/interceptor/command paths and save/reload/clear coverage. Command undo restores captured snapshots with `buildCustomFieldResetMap` from the integrity/concurrency procedure.
- Bulk actions: guarded mutations/commands, progress/cancellation, partial-result reporting; no silent client mutation loops.

Test list/detail/create/update/delete, validation, current/stale version, clearing, denied/wildcard ACL, and the exact response-to-form mapping.
