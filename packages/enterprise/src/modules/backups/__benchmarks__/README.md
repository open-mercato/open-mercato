# Isolated backup performance fixture

This is an opt-in destructive **disposable Docker fixture**, not a production command. It creates/replaces only the `source`, `target` and `baseline` databases inside its dedicated container. Never point it at another PostgreSQL server. Set `OM_BACKUP_BENCHMARK_ISOLATED=true` only in that fixture. No production credentials or keys are needed; it generates a private synthetic recovery identity and validates complete ordered content digests.

Bundle `backup.mts` with the repository's esbuild for Node 24, platform `node`, ESM, `pg-native` external, and a `createRequire` banner. Build this directory's Dockerfile (its Node 24 builder compiles `evict.c`), then create a uniquely named container and disk-backed volume with `--cpus 4 --memory 8g`. Use a generated fixture-only `POSTGRES_PASSWORD`, `PGDATA=/var/lib/postgresql/data/pgdata`, and copy the bundle to `/opt/benchmark.mjs`. The image provides PostgreSQL 16 client tools and Node 24.

Run `node /opt/benchmark.mjs 1` and `20` for the two fixture sizes. Rows contain 64 KiB of generated repetitive text in EXTERNAL storage, so they exercise real TOAST I/O and bounded chunk planning while remaining compressible. This is not an incompressible-entropy benchmark. Preserve `/bench/report.json` after each run. Before another run in the same container, move the previous `baseline.age`, `baseline.dump` and `report.json` aside; artifact publication refuses overwriting them.

For the cold variant, first finish a warm run, cleanly stop **that task's container**, and run `/opt/evict /var/lib/postgresql/data/pgdata` in a one-off container mounting **only that task's volume**. The helper advises eviction of clean pages of regular files only; it does not issue a global cache flush or traverse symlinks. Start a fresh PostgreSQL container on the same volume, copy the same bundle, and run the same size with `--reuse-source --cache-cold`. The expected full source digest is loaded from the warm run's private volume record, so computing it does not warm source data before the cold backup. The native comparison runs after the engine and may have a cache advantage; disclose this conservative comparison in results.

The report separates backup, offline verification, full-mode restore and matched native `pg_dump + age` / decrypt + `pg_restore` timings, sampled coordinator RSS, content equality and the specification's latency/memory conditions. It does not certify other hardware, all data distributions, all jobs settings or a deployment's real key custody. Keep helper source, bundle hash, image identity, cache protocol, command, output and tested commit with published results. Stop/remove only task-owned containers and volumes after copying sanitized reports; generated identities remain private.

`resume.mts` reuses the one task-generated `/bench/output` artifact and its synthetic private identity after a completed main run. It creates only `om_backup_resume_benchmark`, interrupts after one committed data chunk, resumes with a fresh challenge, checks the complete ordered content digest and removes that database in `finally`. Its measured overhead includes fresh challenge, authenticated metadata, journal binding, verification of unfinished chunks and journal initialization; data loading after initialization is excluded. The fixture derives its trusted manifest digest locally only because this process generated and controls the private fixture; real recovery must use the independent trusted digest described in the operator runbook. Bundle this helper with the same Node/pg options as `backup.mts`.

`progress.mts` replays 10,000 entities with 32 chunk events each through every production renderer. Supply the same runner's measured backup duration in `OM_BACKUP_PROGRESS_REFERENCE_MS`; the report compares rendering CPU time against that duration. The byte-counting sink excludes terminal-device I/O and avoids retaining output. Preserve locale asset layout when bundling: `/opt/backups/lib/engine/progress.mjs` resolves `/opt/backups/i18n/en.json`. Report the runner and this scope alongside the result.
