## Interpretation and remaining limits

`DB_POOL_MAX=1` is inherited from the restricted runtime. Peak HTTP overlap is measured on the client and proves outstanding requests, not simultaneous database execution or backend arrival. PostgreSQL serializes the protected work through one runtime connection; queued reuse is intentional. p50/p95 cover all four operations per level and include HTTP overhead, pool wait, auth and application work. Unexpected statuses, malformed responses, timeouts and transport errors increment errors. Invalid successful read responses or accepted foreign writes increment isolation violations; retained-row mismatch independently fails the level.

This test covers authenticated own/foreign reads and forbidden foreign update/delete. It does not establish successful own-tenant mutation behavior, off/on overhead, checkout counts, server-side pool wait, multi-connection SQL overlap, browser behavior, global table enrollment or detached invocation cleanup. Those remain separate acceptance coverage in the enterprise RLS spec. No production business implementation or central domain import is introduced.
