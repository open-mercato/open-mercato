# Brief: wic-score-skill — per-PR partner self-scoring of WIC contribution

Date: 2026-09-01
Routing: om-auto-write-spec (decided in agents-master brainstorm, session cez/ec044aff)
Owner of open payout decisions: Maciej (matgren)

## Goal

A partner runs one skill against their own **merged** PR and gets a WIC verdict they
post as a PR comment: score, base classification with a rubric-row citation, and
bullets explaining every point and every zero. The comment is the ledger entry.
Fairness comes from replayability (a merged PR is immutable — anyone re-running the
skill on the same PR must get the same verdict) plus Core ratification, not from
trusting the model.

This replaces the monthly-batch design of the earlier `wic-evaluator` skill
(commit `6d28c125c` in this repo, PR #1703, closed unmerged). Two companion input
files in this directory preserve the prior session's analysis:

- `2026-09-01-wic-fix-plan-input.md` — accounting model + fetcher/rubric fixes (F1–F5, R1–R4, C1–C2)
- `2026-09-01-wic-test-cases-input.md` — test corpus (S/M/R layers)

Both were written for the monthly-batch shape; this brief states which parts carry
over and which the per-PR reframe deletes.

## Decided model

**Unit of invocation = one PR.** Input: PR URL. Partner-invoked, self-service.
Monthly totals are a projection over ratified verdicts, computed owner-side — not
this skill's job.

**Unit of record = merge.** Only a PR merged to a long-lived branch (`develop`
where it exists, plus the default branch) of a public, non-archived repo in the
`open-mercato` org books anything. Closed-unmerged scores 0, immediately, with the
rule cited. No acceptance-signal mining from comments, no self-certification, no
unmerged-with-APPROVED path (fix-plan R1 — carried over).

**Mechanical gates first** — each can zero the PR with a reason:
1. repo is public and non-archived in the org
2. base ref is long-lived
3. head ref is NOT long-lived (rollup exclusion — release PRs book nothing)
4. PR is merged

**Facts from the PR API, not the search API.** Files, path prefixes (packages /
modules), test paths, additions/deletions, `baseRefName`, `headRefName`,
`mergedAt`, `closingIssuesReferences`, body. All immutable after merge, so the
"frozen fixture" is just the canonical JSON of one PR; determinism stops being
hard. The search API (with its 1000-result ceiling and `--paginate` breakage —
fix-plan F3) is not used at all.

**The only model judgment left: base class** — 1.0 / 0.5 / 0.25 / 0, citing the
rubric row, conservative on hesitation (cut to 0.25). Everything else is
mechanical:
- Impact bonus (fix-plan R3): +0.25 when the PR touches ≥3 packages/modules
  (path prefixes from files), +0.25 when it touches test paths. Literal constants
  in the rubric.
- Levels: after fix-plan R2, level is a pure function of base points
  (1.0=L4, 0.5=L3, 0.25=L1; L2 retired) — see open decision D2.

**Issue credit (fix-plan M8):** when the scored PR closes someone else's issue
(`closingIssuesReferences`), the same run emits a second proposed entry: 0.25
Accepted Bug Report credit for the issue reporter, booked in the merge month. The
reporter runs nothing. An issue never closed by a merged PR is worth 0.

## Verdict comment contract

One comment on the merged PR, generated by the skill, posted by the partner:
- **Human bullets:** score, base class + rubric-row citation, each mechanical
  bonus granted or not, each gate that zeroed anything.
- **Machine block:** canonical JSON inside `<details>`, including rubric version.
  Monthly summing must be a query over these blocks, not archaeology over prose.

Status is **proposed** until ratified. Anti-tamper: replay on the same PR must
reproduce the number; comment edit history is public.

## Identity and ratification — reuse the partner-request grammar

`.github/certified-partners.yml` (exists upstream) is the identity gate: only
verdict comments from registered accounts count toward monthly sums. The
`partner-request` label stays a priority-queue concern only — NOT a WIC gate
(certification can't be forgotten; a label can).

Ratification mirrors the label flow partners already know: Core reacts/replies on
the verdict comment. Ratified verdicts become the labeled corpus. Auto-trust of
the model's base classification only after measured agreement ≥95% on that corpus
(Karpathy gate) — until then every verdict is proposed-then-ratified. A GitHub
Action that validates the mechanical parts of a posted verdict is future work,
explicitly out of scope for v1.

## Ledger layer (owner-side, out of the per-PR skill, in the spec's scope)

Monthly sum = query merged PRs with verdict comments from registered accounts,
then apply the month-scoped rules the per-PR skill physically cannot compute:
- small-items cap (fix-plan R4): small entries sum to at most 1.0/month, excess
  shown as noticed-but-not-paid
- hotfix dedupe (fix-plan M3): same head branch merged to two long-lived branches
  of one repo books once; key (repo, headRefName)
- month = merge month
- monthly sweep flags merged partner PRs with no verdict comment, so forgotten
  runs don't lose work

The per-PR verdict must say so where relevant ("0.25 proposed; monthly cap is
resolved at the ledger").

## Deletions (relative to commit 6d28c125c and the fix-plan)

1. **Monthly apparatus in the fetcher**: org-wide scan, watermark, date windows,
   multi-profile input, all search-API code (fix-plan F1/F3 mostly vanish — the
   per-PR shape makes them unnecessary).
2. **Bounty branch, entirely.** No `bounty` label exists in the repo; the ×1.5
   "judge business intent" multiplier is the least deterministic rule in the
   guide. Comes back as one paragraph when the first real bounty exists.
3. **The comparator** (`compare_reports.mjs`, 146 lines + smoke test). Scoring
   writes canonical JSON; markdown is rendered from it; replay comparison is
   `diff`. Corpus cases S6/S7 vanish with it.
4. **The "CRITICAL DETERMINISM RULE" prose.** Text does not bind a model; the
   binding form is a replay test in CI: same PR, three runs, identical verdict.
   One sentence in the guide, one test in the corpus.
5. **Markdown branch in the fetcher** (fix-plan F5): JSON is canonical.

## Carried over from the fix-plan (still correct in per-PR shape)

- Hard errors instead of silent nulls: fetch failures throw; `errors[]` non-empty
  → non-zero exit; no artifact written on failure (temp file + `mv`). Retries
  with backoff on 403/429. (F2, F4 minus the parts made moot by dropping search.)
- Comment/review sorting by `id`, codepoint string compares, `generatedAt` out of
  the canonical payload. (F4)
- Version bump to `2.0-agent`; March/April 2026 reports (`.ai/runs/wic/`) were
  produced under the 1.0 monthly model, are not comparable, and never feed tier
  decisions. Their PRs enter the ledger as already-booked so nothing double-counts. (C2)

## Test corpus expectations

- Script layer: S1 (hard error on 403), S4 (edited comment moves one field only),
  S5 (no partial file on crash) still apply. S2/S3 die with the search API,
  S6/S7 with the comparator.
- Gates layer: M1 (release rollup → 0), M2 (direct-to-main books), M4 (repo
  without develop), M5 (private repo → 0), M8/M9 (issue credit), M10 (spec under
  `.ai/` books like any PR) become per-PR gate tests.
- Ledger layer: M3 (hotfix dedupe), R4 cap, month assignment.
- Rubric layer: R1–R3 from the test-cases file as replay cases; every corpus case
  must produce identical verdicts across three runs.
