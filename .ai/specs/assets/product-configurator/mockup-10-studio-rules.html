Studio: rules

Admin defines what blocks, warns, sets values or adds a surcharge, with conditions built from the features.
1
Name and idEach rule has a friendly name for people and a stable id for the model; reports show both.
2
Map actionA “sets a value” rule can swap a field’s current value for another through a small table (here: tyres). Values not in the table stay as they are.
3
Condition builderConditions are picked from features, calculated values, text and lookups, with operators and allowed values; the same editor is used for visibility and BOM conditions.
4
MessagePlain text written by the admin, with placeholders for values. The rep sees only this text, never the id.
5
Map editorRows pick a current and a new value from the field’s options, so a map can only produce allowed values.
6
Highlighted fieldsPrefilled with the features used in the conditions; the admin can add or remove them. Message links on the rep screen go to these fields.
7
Action typesSet a value, Map values, or Default from a permitted lookup. Every editor offers only values the field allows.
