# Warranty portal permissions — issue #9110

## Triage
The linked-customer check authenticates portal users but omits customer RBAC across all warranty portal endpoints. No implementing PR or base commit was found during triage.

## Root cause
A viewer shares the same company pin as a buyer. `lib/portalAuthGuard.ts` never calls `requireCustomerFeature`, and the order, options and troubleshooting builders independently check only identity. Role permissions therefore do not constrain reads or writes.

## Plan
1. Declare portal view/manage features and buyer/viewer defaults using existing module setup conventions.
2. Require live CustomerRbacService authorization before endpoint work; use portal.orders.view for order and line endpoints and preserve ownership predicates and mutation guards.
3. Gate page metadata and prevent replacement/deletion of evidence beyond draft, submitted and info_requested.
4. Add endpoint and role regression coverage; run required validation, review and QA; publish one dedicated PR.

## Migration and compatibility
This intentionally narrows unauthorized portal access as requested by #9110. Buyers retain view/manage and viewers retain view through defaultCustomerRoleFeatures. Existing tenants must run `yarn mercato customer_accounts sync-customer-role-acls`; existing customized grants remain additive. Routes, response shapes, database schema, startup, configuration mechanism and architecture remain unchanged. Evidence replacement/deletion is restricted after review starts; uploads retain existing behavior.
