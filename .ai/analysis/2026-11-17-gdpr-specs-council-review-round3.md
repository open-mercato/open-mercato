# GDPR-ready deployments specs — council review, round 3 (2026-11-17)

Scope: the 49 spec files changed on `feat/8593-gdpr-ready-deployments-spec` for open-mercato/open-mercato#8593. That is the program spec, 39 child specs and the readiness audit, plus the branch edits to 8 earlier specs. The branch was reviewed after merging `upstream/main` at `29770a5cd8` (merge commit `14cec54be1`).

## Verdict

**Not ready to hand to implementers yet, but no redesign is needed.** No blocker survived verification. Reviewers raised 30 blocker findings: 18 from Sol, 10 from Kimi and 2 from DeepSeek Flash. Each was narrowed to major or lower, or refuted against the spec text and the code. What remains is **54 confirmed major issues**, each fixable by editing a spec, plus 173 minor issues and 42 nits. 36 findings were refuted. Every batch asks for changes, so another revision pass is needed before implementation starts. The program spec itself notes that the revisions from rounds 1–2 "have not been re-read"; this round is that re-read.

## How this round was run

- **Council:** four independent reviewer families on every batch, all reviewing the same immutable `om-code-review` packet through the `om-harness` runtime (`prepare-review --kind spec` / `review`):
  - **Opus:** a fresh Claude Opus 5.5 context with repository access. It checked spec claims against the code.
  - **Sol:** `codex` `gpt-5.6-sol`, xhigh effort, read-only sandbox.
  - **DeepSeek Flash:** `deepseek-v4-flash`, high reasoning, tool-free.
  - **Kimi:** `kimi-code/k3.1-pro`, tool-free.
- **Batches:** the roughly 3 MB of specs was split into 8 themed batches. Each batch's criteria carried a digest of the program's decisions and work packages for cross-spec checks.
- **Verification:** every raw finding was clustered and checked adversarially by a fresh Opus verifier against the spec text and the code. Each received a verdict of confirmed, partially confirmed or refuted, and a recalibrated severity. Minority findings were kept.
- **Artifacts:** per-batch packets, raw reviewer results, `merged-findings.json`, `reconciled.json` and `reconciled.md` are in `.ai/qa/gdpr-spec-council-r3/<batch>/` (gitignored).

## Cross-cutting themes in the 54 majors

1. **Phase-order deadlocks and missing dependencies.**
   - A9 is "dependency-free" but needs C1's `PrivacyScope`.
   - C4 Phase 3 and the C7 portal worker each wait on the other.
   - Communication Phase 1 tests people-ops Phase 2 credential methods.
   - E3 Phase 2 waits on Content-AI Phase 1, which already implements E3's own declaration.
   - A1's release gate omits B1 Phase D and the Enterprise vector rotation step, which its refusal text relies on.
2. **Closure gates that can never pass.**
   - C5 closure for `action_logs`.
   - No owner for the `access_logs` retention bound.
   - Tenant-exit exit 0 is unreachable because of `mikro_orm_migrations_*` and `vector_search`.
   - Session-route gateway rows are left on the baseline.
   - C3/C9 tables are `retention_bounded` without `retentionBounds`.
   - The `restore-status --refresh` readiness probe can never pass.
3. **Erasure and export completeness holes found in code.**
   - Message forwards.
   - Chat discovery through `contact_person_id`, which is never written under encryption.
   - Portal workflow tasks.
   - Tpay has no mapper.
   - Whole customer/address snapshots kept on retained orders.
   - Employment free text kept under legal retention.
   - Async search-index and form-to-deals cleanup reported as complete.
   - An absent root returns `not_found` and so orphans dependants.
   - Unbounded single-transaction class erasure.
   - Delayed or parked queue copies.
4. **Cross-spec contract contradictions.**
   - The DSR register-policy result shape does not match ROPA's.
   - R4-3 cites an audit method that does not exist, for rows that cannot exist.
   - The SCIM 400 from R5-4 conflicts with DEC-5 and with a stale 503 elsewhere.
   - DEC-11's "every model route" list is incomplete.
5. **Security gaps.**
   - Portal email-change recovery leaves the attacker able to sign back in.
   - Passwordless identity moves need only a fresh session.
   - Restore manifests are unsigned.
   - `allowUnmatchedHolds` is not gated by hold-release permission.
   - The search-index listing ignores the organization allowlist.
   - An organization AI row silently overrides tenant enforcement.
   - Undo leaves a pay-link page public.
6. **Backward compatibility and operability.**
   - `customerTokenService` overrides break with no bridge.
   - The SCIM 400 has no bridge minor.
   - KMS `fail` mode refuses tenantless commands.
   - The audit-history cleanup is specified as a single-transaction migration.
   - The 1,000-records-per-day retention budget is too low for busy tenants.
   - The access-log fallback probe stalls under default windows.
   - The prescribed Meilisearch rebuild wipes other organizations' documents.

### Coordinator decisions that settled conflicting fixes

- **D1 — R4-3:** tenant-export evidence always carries its tenant. The code has no `privacy.tenant_export` kind and no null-tenant count, and deleting a tenant is a soft delete. The installation-scope retention mode is therefore removed everywhere: `runInstallation`, `--installation`, `OM_PRIVACY_INSTALLATION_EVIDENCE_AGE_DAYS` and `installationExcludedSubjects`.
- **D2 — R5-4 SCIM:** plaintext identities keep unlimited SQL equality. Ciphertext identities use a decrypting scan of at most 100, then HTTP 400 from minor N+1, one warning minor later. The doctor error `sso.scim_lookup_secret_missing` fires only when `sso` is enabled, encryption is on and no lookup secret is set.
- **D3:** program package A9 alone delivers the integrations credential methods.
- **D4:** the DSR register-policy result uses the ROPA shape, including `targetMode`.
- **D5:** form-to-deals uses a `downstreamCleanup` hook. The shared `PrivacyDownstreamCleanup` type lives in C1 and is awaited by C4 step 8, which plans again after the write barrier.
- **D6:** `applyRetention`'s result is unchanged. The replay-rollout warning comes from `actionLogService.isReplayRolloutConfirmed()`.
- **D7:** the caller argument of `clearSourceForErasure` is `callerModuleId`. The only exception is the legacy unprefixed `message` type, which is allowed for `messages`.

### Design changes worth a maintainer's sign-off

These go beyond restating the original intent:
- **A1 release gate:** widened, and it no longer depends on Enterprise. It now needs B1's store-owned rotation classifier, `backfill-encryption`, B1 Phase D items 2–3 and B4's vector reseal.
- **New CLI commands:** `mercato search reindex-tokens` and `mercato audit_logs confirm-replay-rollout`.
- **Restore manifests:** signed with the new `OM_ERASURE_MANIFEST_SIGNING_KEY`. The readiness probe accepts exits 0 and 3, so a manifest-directory outage no longer takes the app down. An unreviewed restore still blocks.
- **Disclosed, not gated:**
  - A transient KMS outage writes plaintext, and the AI provider allow-list stays advisory. Both are disclosed under Known limits.
  - OSS ordinary action-log history closes C5 as a named `known_limit`.
- **Behaviour changes:**
  - Restricted admins' fulltext rebuild only upserts their own organizations.
  - An organization's AI row can only narrow the tenant's.
  - An erased closed warranty claim cannot be reopened (409).
  - Tenant export keeps numeric token-usage counters through `reviewedScalars`.
- **Form-to-deals:** becomes the core module `packages/core/src/modules/form_to_deals`, with no official-modules package.
- **Still to do:** program Phase 0 must open the `AGENT-PROCESSLESS-RETENTION` tracker issue under #8593. It has not been opened yet.
