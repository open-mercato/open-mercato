#### What human QA should verify

- Login injection: on a fresh /login load, an enabled alternative provider appears with translations and its override submission/reset works; ordinary password login still works after reset (#8370). In the same browser, select All organizations, sign out, sign in as another staff user, and confirm the new user starts in an authorized organization and can create a record (#7516).
- Live revocation: warm a disposable user's staff/portal session and session API key, then deactivate that user or its tenant from an independent administrator session. Existing requests, refresh and fresh sign-in must fail; SCIM active:false must also deny both local-password and SSO sign-in, and active:true allows a new sign-in without restoring revoked sessions (#8245, #8172, #8088). Keep a separate recovery administrator.
- Grant/target scope: remove a role or ACL grant while a user is signed in, then retry its privileged action and a guessed foreign-tenant target. Revoked live grants must cease granting access, and foreign targets must stay inaccessible; do not infer authorization from hidden menu items alone (#5770).
- API-key scope: an unrestricted creator can list tenant-wide keys together with the selected organization's keys; a restricted actor sees only allowed organizations and no other tenant. A user-bound key may read its own profile/layout with its effective feature ceiling, but unbound or foreign-user bindings fail and profile PUT cannot exchange the key for a full interactive session. Exercise these API-only checks with a credential-isolated client (#8273, #8219).
- Passkeys/MFA: on a disposable account enroll through the real browser WebAuthn ceremony, then sign in using that key; a crafted legacy public-key-only enrollment must return 400 without activating a key. In an isolated security test setup, trigger the documented emergency MFA bypass and verify one warning per organization/UTC day reaches eligible security administrators, while access is not delayed by enqueue failure (#6824, #7619).
- Organization domains: with domain-manage permission only in organization A, list/create/verify/delete/health-check A's mapping successfully; a crafted request targeting organization B or linking B's mapping as a replacement must fail before mutating B (#8167). Use disposable domains rather than production routing.
- Owner-protected attachments: share a disposable document and verify the authorized viewer can list/download its original file and thumbnail. Revoke the share or documents.view and retry cached URLs in the restricted and anonymous browser: reads must be denied, hidden entries excluded from counts, and fresh watch/mention notifications suppressed. Inspect headers: owner-protected content is private, no-store; other scoped public-partition content is private, max-age=60, while genuinely global public content remains anonymously readable (#6829, #8180, #7986).
- Public Forms participant roles (optional Forms module): an editable attachment field accepts an upload; a read-only participant may download but cannot upload; hidden or undeclared fields and attachments return the same generic 404. Repeat with an attachment from a different submission (#8147).
- Encryption/operator boundary on disposable data: create/edit/read an Encrypted custom-entity value and confirm authorized UI reads remain usable while database document storage is ciphertext. A notification action may run only its declared authorized command; a crafted unrelated command or a recipient whose feature was revoked must fail without side effects (#8220, #7669). - CRM privacy and references: on /backend/customers/people → a disposable record's activity timeline, a manager who cannot read another user's private email must not expose it by changing author/type/visibility, completing, cancelling, deleting or replaying undo/redo; share it explicitly and verify only the allowed shared edits work, then revoke the share. Scheduling for that colleague must not disclose the private email title in conflicts. A crafted interaction owner/author assignment must reject missing or foreign-tenant users, while valid same-tenant cross-organization attribution and historical offboarded authors remain readable (#8358, #8027, #7935).
- Deal pipeline boundary: on /backend/customers/deals → create/edit a disposable deal, select a valid local stage without supplying a pipeline and confirm its parent is inferred. Using an isolated API client, substitute a stage or parent-pipeline ID from another tenant/organization or an unknown ID; expect a translated reference rejection and no deal, dictionary, stage or transition-history mutation (#7950).
- Organization lifecycle: on /backend/directory/organizations create a disposable organization, note its ID/creation time, undo, then redo; it is soft-deleted/deactivated on undo and restored with the same identity/time on redo. Reproduce B under A → detach B → move A under B → undo detachment: the replay must refuse the cycle and leave the valid hierarchy unchanged. Denied writes must return the configured refusal with no side effect; with an allowing guard the normal action succeeds, and a failing after-commit callback must not turn an already committed write into an HTTP failure. Use scoped staff grants rather than an auth.features claim (#8019).

Exact-boundary valid payloads retain normal behavior; oversized bodies return 413 before verification/parsing/candidate lookup/command execution, with no downstream side effect. #### What can go wrong

- A warm authentication or ACL cache continues accepting a suspended tenant, deactivated owner or revoked grant.
- Alternative sign-in disappears, organization scope persists across users, or the CSP blocks hydration, payment widgets or collaboration.
- A protected file or document title is disclosed through a thumbnail, cached response, list count, notification, public form role or foreign organization mapping.
- Required deployment remediation is missed: clear legacy shared-cache copies for scoped attachments; audit existing plaintext and historical passkeys; deploy auth enforcement to every process. At-rest encryption alone does not grant read-side authorization.

B cannot read, confirm or cancel A's action, even with its ID (404); A retains access. - Stale bulk preview: stage updates to two products, edit one manually in a second session, then confirm. Only the unchanged previewed row is updated; the manually edited row retains its human value and is reported stale_version. If every row is stale, confirm returns 412 and writes nothing. - Delegated-key ceiling: issue a disposable AI/MCP session key to a user with a narrower UserAcl than its roles, remove a role or organization grant, and retry a privileged read/write using the already-warmed key. - Search privacy: create a person/company and an encrypted custom field containing unique synthetic email/phone and secret markers. Reindex using the supported environment process. - Network boundary (controlled test harness): make Code Mode api.request() encounter 301/302/303/307/308 and same-origin chained redirects; it returns a safe error with the original redirect status and does not forward credentials, scope headers, request bodies or redirect contents. #### Where QA should click

- Broad smoke: `/login` → `/backend`; open an existing CRM record, a catalog product and an order after deploying the tested build.
- Engineering-owned checks: scaffold a temporary standalone app and use the module catalog search/info and picker flows; inspect CI and container build evidence without exposing environment files.

#### What human QA should verify

- The deployed build starts and navigation works; linked specs are readable design proposals, without asserting that bookings, CPQ, recurring orders or other spec-only features exist.
- Module catalog search ranks exact identifiers correctly, module info/download failures are clear, and adding/enabling an already-enabled module succeeds without duplication or losing comments or environment-gated entries (#8118, #8117, #8190, #8122, #8116, #8114). Engineering should verify the standalone server avoids full bootstrap and generator memory measurement remains reproducible (#8337, #8336).
- Engineering verifies container build contexts exclude environment files, service ports remain private behind the proxy, and CI preview publication requires independent approval (#8195, #7993, #7987). Docs middleware traversal defenses need security-test evidence (#8181); a browser happy path cannot establish them.
- The decision-model adapter port (#7553) is infrastructure without a product consumer in this change: review adapter/fixture tests and configuration documentation rather than inventing a playground toggle.
- Engineering registration check (#7245): enable a setup override, register the full module registry, then load a translation-only batch. Registered modules/features and default grants must remain intact, and an authorized employee must still reach a feature-gated backend page. A basic startup check alone does not reproduce this regression.
- Initialization check (#6724): initialize only a disposable empty database using a superadmin email on a non-default domain; derived admin/employee accounts must use that domain and authenticate with the intended scoped features. Do not reinitialize a shared QA database.
- OCR operator check (#6435): use controlled extraction timeout and cancellation fixtures. The reported error must identify timeout or abort rather than blame a missing API key; genuine missing-credential errors remain distinct. Retain error-mapping test/log evidence without credentials.
- CI-only and test-stabilization changes require check-run evidence; a skipped test is not evidence that the product behavior passed. Dependency bumps get startup and relevant feature smoke, with provider-specific coverage delegated to their product route.

#### What can go wrong

- A green admin smoke can conceal failed CI, exposed container files/ports or insecure package preview publication; retain engineering ownership for these checks.
- Scaffolding may differ from the monorepo; dependencies or module discovery can break only in a clean standalone app.
