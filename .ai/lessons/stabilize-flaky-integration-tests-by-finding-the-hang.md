# Stabilize flaky integration tests by finding the hang, not by raising the timeout

**Context**: `TC-CUR-004` ("Set Base Currency from UI") failed ~1/60 in the `ephemeral-integration` CI shards with `Test timeout of 30000ms exceeded` plus a secondary `apiRequestContext.fetch: Target page, context or browser has been closed` reported from the `finally` teardown.

`TC-WC-023` failed after successfully receiving and quarantining a claim line because it required the emitted event to remain in the local queue file. The ephemeral harness runs queue workers concurrently, and the local strategy removes completed jobs, so queue residency was a race rather than durable evidence of emission. The stable assertion accepts either a still-queued job or the command's durable `line_received` quarantine timeline record.

`TC-WC-040` inspected and received the last line of 101/200-line claims, then timed out opening vendor recovery. The failure screenshot showed the Actions menu closed. `ActionsDropdown` opens on hover and toggles on click, so a pointer click can immediately close the menu it just opened. Check `aria-expanded` before keyboard activation, assert the target menu item is visible, and activate it with the keyboard to avoid hover-driven toggles.

The next run opened recovery and confirmed the last line was selected, then hung on a vendor-name label lookup. The recovery form's builtin text field had a visual label without an associated accessible label. Inspect the rendered field before choosing a locator; for this existing CrudForm surface, scope to its stable `data-crud-field-id` wrapper and then the textbox role, following the other integration suites.

Once both recovery flows completed, the 200-line case exceeded its teardown budget on serial API deletes. Gather all pages before mutating, delete distinct fixture lines with bounded concurrency and their own versions, then serialize one final delete so aggregate rollups reflect the fully completed batch before lifecycle cleanup. Keep every response assertion and cleanup dependency instead of extending the timeout or leaving fixtures behind.

On the newer base, the workflows still completed but the 200 versioned deletes exceeded the shared 20-second hook budget under CI load even after batching. Give this teardown its own bounded 60-second budget, following the existing RMA long-flow convention, while preserving the 20-second user-flow limit and every response/version assertion. If a grading-dialog click leaves the dialog closed, retry only while it is closed and assert that it opened within a short bounded window before filling fields; do not let a never-opened dialog consume the whole test.

Preserve UTF-8 when renaming tests or rewriting accessible-name literals. Windows PowerShell can decode a UTF-8 file using a legacy encoding and then save mojibake as valid UTF-8. Use an encoding-aware patch or explicit UTF-8 reads and writes, and compare the renamed file against its prior contents with only the intended identifier replacement applied. A Unicode locator mismatch is not evidence that the rendered control is missing.

`TC-CRM-065` selected ten unfiltered people although its scenario created three fixtures. The matching search response arrived after deletion. An exact response/fixture-row guard prevented that mutation, but a cold local attempt still timed out with an empty search field; the passing retry's trace showed typing overlapping the initial client fetch. Wait for a row populated by the client effect before typing, then verify the filtered response IDs, rendered rows, and selected count before any bulk mutation.

**Problem**: The secondary "context closed" error is a symptom of the test-level timeout tearing the worker down mid-request — it is not the cause. Two real causes hid behind it: (1) the row-actions dropdown is opened with `actionsButton.press('Enter')` and then the menu item is clicked directly; if the Radix trigger swallows the keypress before hydration, the menu never opens and `.click()` auto-waits on a never-mounting element until the whole test times out; (2) login + navigation + three sequential ≤10s waits + fixture setup/teardown genuinely does not fit a 30s budget under 15-shard parallel load — every other login+nav spec already uses 60–120s, and this one was the lone 30s outlier.

**Rule**: When an integration test "times out," read the trace to find which await actually blocked before reaching for a bigger number. Make UI interactions deterministic: after a keyboard-driven menu open, assert the target item is visible with a *bounded* budget and fall back to a pointer click, so a missed keypress fails fast instead of hanging until the suite timeout. A click on server-rendered markup can also land before React hydration; poll the first observable state transition and retry only while the component is still idle. For unit tests of intervals, retries, leases, or heartbeats, do not assert after a short wall-clock sleep: wait until the operation has reached the state that installs the timer, then advance fake timers by the exact interval. After enqueueing work, assert a durable outcome or an allowed state transition instead of requiring a transient `pending` snapshot that a faster worker may already have advanced. Overrides that wrap an interactive login surface must be registered before that surface hydrates; activating the wrapper later remounts uncontrolled inputs and can erase credentials typed by autofill or a fast user. When the scenario targets a specific lifecycle hook, use a least-privilege fixture so a higher-priority optional widget cannot correctly intercept the mutation first and mask the hook under test. Parallelize independent fixture requests and teardowns while retaining dependency ordering instead of spending the test budget on serial setup. Make `finally` teardown best-effort (`.catch(() => {})`) so it cannot mask the real failure with a "context closed" error. Only after removing the hang should you align the per-test budget with the established login+nav convention. Prefer fixing the interaction over inflating the clock.

**Applies to**: every Playwright spec under `**/__integration__/*.spec.ts` that drives `RowActions`/dropdown menus or client-hydrated controls, login surfaces extended through component overrides, every lifecycle test where optional injection widgets share the same host, any spec whose `finally` block issues API calls after the body may have failed, and unit tests that prove queue lease renewal or other timer-driven concurrency behavior.
