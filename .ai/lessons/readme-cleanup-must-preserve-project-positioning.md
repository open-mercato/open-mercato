# README cleanup must preserve project positioning and voice

**Context**: A request to remove generic presentation, decorative icons, and duplicated README content was treated as permission to replace the project's opening positioning statement with new copy. The rewrite retained several factual claims but removed the established audience, framing, and voice.

**Problem**: Product positioning is not interchangeable with a feature summary. Even when a replacement is cleaner or more concise, rewriting it can change the project's identity, target audience, and claims without explicit approval. A request to improve presentation does not automatically authorize editorial repositioning.

**Rule**: During README cleanup, preserve positioning statements and voice-bearing passages verbatim unless the user explicitly asks to rewrite them. Improve layout, remove decorative clutter, consolidate genuinely duplicated reference material, and correct only specifically approved wording. If a passage appears inconsistent with the requested tone, identify it separately and ask before replacing its message or voice.

**Applies to**: Repository landing pages, product introductions, taglines, audience statements, value propositions, and other public copy whose wording carries project identity rather than only technical facts.
