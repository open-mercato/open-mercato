## Step 0 — Agentic setup (replace the rule sources)

This repository has no `scripts/lint.sh`, `om-filozofia.md`, or `DECISIONS.md`. Load these instead; the base skill's own `references/` files still apply unchanged:

## Steps 1–2 — Mode and authoring (replace the target tree)

- Read every `skills/<name>/` in the base workflow as `.ai/skills/<name>/`. Split mode works only on a local skill (one listed in a tier). A name in `external.skills` belongs to open-mercato/skills: change it there, or write an overlay for this repo's delta.
- Generic briefs belong in the shared collection. If a brief would work in any repository, say so before writing a local skill.
- **Name**: `om-` prefix, kebab-case, verb-first, at most 64 characters. It must not already be used by a folder under `.ai/skills/` or by an entry in `external.skills`, because a folder named after an external skill is treated as an overlay and is never installed as a skill.
- **Frontmatter**: only `name` (equal to the folder name) and `description`. Tier membership goes in `tiers.json`, never in frontmatter. `description` stays under 1024 characters and contains no `<` or `>`.
- **Scope of the lint rules**: the base skill's forbidden-token rules (product name, package scope, base branch, package manager, direct tracker CLI) guard the collection's `skills/` tree. Local skills here are Open Mercato specific and may name packages, modules, `yarn` scripts, and `develop`. PR/issue work still follows root `AGENTS.md` and `.ai/docs/pr-workflow.md`.
- Write instructions in the imperative. Keep `SKILL.md` under 500 lines and move the rest to `references/`.

## Step 2.1 — Overlay branch (extend: overlays in this repository)

- Register the overlay by adding the name to `external.skills` in `tiers.json` (never to a tier) and to the external list in `.ai/skills/README.md`.
- Shape: the base `references/overlay-contract.md`. Measure the 50% limit against the installed base at `.agents/skills/<name>/SKILL.md`. Some older overlays here still carry frontmatter. Normalize one only when you are already editing it.
- To retire a local skill in favour of a collection skill: delete the local folder, move the name from its tier to `external.skills`, keep only this repo's delta as an overlay, and rename every reference you find with `git grep -n <old-name>`.

## Step 2.4 — Scaffold (add: register the skill)

A new local skill is not finished until it is registered:

1. `.ai/skills/tiers.json`: add the name to exactly one tier. `core` is installed for every contributor and costs context in every session, so prefer an opt-in tier unless the skill is used daily.
2. `.ai/skills/README.md`: add a row to that tier's table under "Available Skills", with the `description` copied verbatim into "When to use", and update the tier's count in the "Tiers" table.
3. Root `AGENTS.md`: add or extend a task-router row only when a task area should point at the skill.
4. Apps generated by `create-mercato-app` have a separate skill tree. Only when the skill must ship there, follow `packages/create-app/AGENTS.md`.

## Step 4 — Gate 1, lint (replace)

```bash
node scripts/validate-skills-tiers.mjs   # CI runs: bash scripts/validate-skills-tiers.sh
yarn install-skills --list               # the skill appears in its tier (or under external)
```

The validator does not cover two checks the collection lint makes, so run them by hand: the frontmatter matches the rules above, and every bundled-file pointer resolves:

```bash
SKILL=<skill-name>; dir=".ai/skills/$SKILL"
grep -rhoE '(^|[^A-Za-z0-9._/-])(references|scripts|assets)/[A-Za-z0-9._/-]*[A-Za-z0-9_-]' "$dir" --include='*.md' \
  | sed -E 's#^[^rsa]##' | sort -u \
  | while read -r p; do [ -e "$dir/$p" ] || [ -e "$p" ] || echo "MISSING: $p"; done
```

Fix every `MISSING:` line, or confirm that it names a file in another tree on purpose. Then install the skill (`yarn install-skills`, adding `--with <tier>` for an opt-in tier) and invoke it once. Gates 2–5 apply unchanged, with `skills/$SKILL` read as `.ai/skills/$SKILL`.
