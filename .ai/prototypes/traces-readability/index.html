TermsPrivacy
1Seven equal-weight cards, all expanded, in storage order rather than reading order. Nothing on the page states the one thing every reader opens it for: what the run decided, and whether that was right.
2The failure reason lives only inside a card. errorMessage exists on the record but never gets headline treatment.
3Model comparison is a cost-optimisation feature sitting inside a debugging page — a different job for a different person.
4Reasoning and tool payloads are the highest-volume and lowest-frequency-of-need content on the page, and they are inline and expanded.

TermsPrivacy
1Two readers, stated openly. Review answers "was this right?" for an operator; Debug holds spans, tool payloads, reasoning, context and artifacts for whoever is fixing the agent.
2Follows a pattern already in this repo: the workflows run detail is Flow / Timeline / Context / Raw. Consistency with it is an argument on its own.
3The count badge on Debug tells an operator how much is under there without opening it.
4Costs a decision — every field must be assigned an audience. Some, like confidence, legitimately belong to both.
