Checkout Funnel — screen inventory

Derived from .ai/specs/2026-03-19-checkout-simple-checkout.md. Screens 1–16 are the buyer-facing funnel (apps/storefront's checkout/ route) — the same deliberate om-mockup-prototype scope exception as the storefront-app prototype, storefront top-nav chrome rather than the backend AppShell. Screens 17–18 are the module's one genuine backend surface, checkout.sessions.view/.manage (§9) — those need no exception and use the real AppShell. This set aims for full behavioral coverage of the spec: every step (§5.2), the stale-rate bounce-back (§5.2/R5), both submit outcomes (order/quote, §8.1), every named submit failure and compensation trigger (§7.2, R1–R10) that has buyer-visible behavior, the B2B approval gate and its re-approval edge case (§8.2, R8), the cart-lock conflict a second tab sees (§6), and the admin session/event-trail viewer (§9). Not drawn: literal combinatorics of every field-validation message, and Phase A pay-link entry mode (§3.2) — noted in-line instead, since it reuses an already-implemented, already-shipped flow this suite doesn't touch. Tenant: Northwind Fasteners, continuing the suite's sample data.
