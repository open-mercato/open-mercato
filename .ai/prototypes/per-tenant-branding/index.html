Per-tenant branding — screen inventory

Clickable low-fidelity prototype derived from .ai/specs/enterprise/2026-11-13-per-tenant-branding.md. Screens 1–6 cover the Enterprise Settings → Branding page, and screens 7–10 show the branded login, backend and portal shells on first paint. It is fully offline: no fonts, images or scripts load from the network. Sample data is fictional.

10. Fallback — unknown tenant or provider failure

If the tenant is unknown or inactive, or the branding lookup fails, every shell renders the platform defaults and never errors.

Edge CasesUS-B10US-B12
/login?tenant=not-a-real-tenant
OM

Open Mercato

resolveTenantBranding(container, { tenantId, organizationId, surface: 'auth', host: null }) → tenantId not a UUID → null (provider not called) → provider timeout (2 s) → reportError, null, 30 s circuit for this tenant → invalid style in DB → style dropped, logos + name kept → module disabled → noopTenantBrandingProvider → null
1An unknown tenant id gives no distinct error and reveals nothing beyond what the existing tenant lookup already exposes.
2This is also exactly what every OSS app renders, because the no-op provider is the default.
