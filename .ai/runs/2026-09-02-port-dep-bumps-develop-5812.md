# Execution plan — port dependabot minor/patch bumps to `develop` (#5812)

## Goal

Land the dependency updates of [PR #5812](https://github.com/open-mercato/open-mercato/pull/5812) (`chore(deps): bump the minor-and-patch group with 47 updates`) on `develop`, the repository's configured base branch, and close the original PR — which dependabot opened against `main`.

## Context

- `main` is fully contained in `develop` (0 commits on `main` that `develop` lacks); `develop` is 160 commits ahead.
- Because dependabot targets `main`, its bumps never reach the branch every feature PR is cut from. Porting is a straight forward-port, not a merge.
- `develop` carries two workspaces that do not exist on `main` — `packages/documents` and `packages/channel-discord` — plus a moved `html-to-text` dependency (`core` → `shared`) and a trimmed root `resolutions` block. The port must therefore be applied by dependency name across the **current** workspace set, not by replaying the diff hunk-for-hunk.
- The root `package.json` `resolutions` block pins several of the bumped packages (`ai`, `esbuild`, `pg`, …). Those pins override every workspace range, so they must move together with the ranges or the bump is inert.
- `.yarnrc.yml` sets `npmMinimalAgeGate: 5d`; any target version published less than five days ago will be rejected at install time and must be left at the highest reachable version, with the gap recorded.

## Scope

- Every workspace `package.json` on `develop` that declares one of the 47 bumped packages.
- The root `resolutions` block.
- `yarn.lock`, regenerated by `yarn install`.
- Closing PR #5812 with a comment pointing at this port.

## Non-goals

- No source changes. If a bumped package needs a code migration, that is a separate PR and this run stops and reports it.
- No major-version bumps — this is dependabot's `minor-and-patch` group only.
- No change to dependabot's own configuration (retargeting it at `develop` is a policy decision for the maintainers; flagged in the PR body, not made here).
- No changes to `external/official-modules`.

## Risks

- **Resolution drift.** Regenerating `yarn.lock` re-resolves every `^`/`~` range that changed, so the resulting versions may be newer than the ones dependabot pinned against `main`. Acceptable — the ranges are what the repo commits to — but the validation gate is what proves it.
- **Age gate.** A target version younger than 5 days is unreachable; the range is then left at the highest installable version rather than forcing `--no-time-gate`.
- **Runtime breakage from a patch bump.** `next`, `@mikro-orm/*`, `ai`, `pg` and `react` all move. Only the full validation gate (build:packages → generate → i18n checks → typecheck → test → build:app) can catch this, so it runs unabridged.
- **Dependency-consistency guards.** `develop` adds `check:dep-versions`, `check:resolutions` and `packages:check-peer-deps`; a partial port trips them.

## Implementation Plan

### Phase 1: Port the version bumps

1.1 Extract the name → old/new version map from #5812's `package.json` diffs and apply it to every workspace manifest on `develop`, including the `develop`-only `packages/documents` and `packages/channel-discord`, keeping any range already at or above the target.
1.2 Update the root `resolutions` pins for the bumped packages so they do not override the new ranges.
1.3 Regenerate `yarn.lock` with `yarn install`, recording any version blocked by the 5-day age gate.

### Phase 2: Validate

2.1 Run the repository's dependency-consistency guards (`check:dep-versions`, `check:resolutions`, `packages:check-peer-deps`).
2.2 Run the full configured validation gate in order.

### Phase 3: Land and close the original

3.1 Open the port PR against `develop`, then close #5812 with a comment naming this PR.
