# 0.7.0 release changelog and upgrade companion

## Goal

Prepare the Open Mercato 0.7.0 release documentation from every pull request merged into the parallel `develop` line from 2026-07-29 through 2026-08-12, excluding work already shipped in v0.6.7/main, and align the matching downstream upgrade window with an installable migration companion.

## Scope

- Prepend the 0.7.0 changelog block in the repository's established emoji-driven format.
- Consume all 258 eligible pull requests merged into the parallel `develop` line from 2026-07-29 through the final 2026-08-12 snapshot at `6a29a6417`; exclude work already present in the v0.6.7 release/main history, exact patch duplicates, already-shipped sync containers, and prior changelog PRs.
- Resolve all 67 detected supersede chains, including carried-forward original contributors where the merged PR records them.
- Reconcile `UPGRADE_NOTES.md` from `0.6.7 → 0.6.8 (unreleased)` to `0.6.7 → 0.7.0 (2026-08-12)`.
- Add `om-auto-upgrade-0.6.7-to-0.7.0` to the monorepo and byte-identical standalone skill surface, both migration tiers, the skills README, and the help catalog.
- Keep release-contract coverage green through the existing create-app contract test.

## Non-goals

- Do not change package versions, dependency pins, release tags, runtime code, or any PR outside this dedicated release-artifact PR.
- Do not include open PR #4840 or any other work that has not merged into `develop` in the changelog.

## Implementation Plan

### Phase 1: Release inventory and changelog

- Categorize all eligible merged PRs using the configured label and conventional-title precedence.
- Normalize summaries, resolve supersede credits, build the contributor list, and prepend the 0.7.0 entry without duplicating prior release work.

### Phase 2: Upgrade companion

- Reconcile the matching upgrade heading and classify every 0.6.7-to-0.7.0 downstream action as automatic, detect-and-report, or no-code-action.
- Add the bounded, idempotent migration skill to both agent surfaces and register/document it in both migration tiers.

### Phase 3: Verification and review

- Run the focused release-contract checks, both skill-tier validators, create-app tests, and the configured validation gate selected by the delegated PR workflow.
- Run the authoritative PR review/autofix pass, publish the complete verification summary, and mark the PR ready when clean.

## Risks

- The parallel-development cutoff predates the v0.6.7 tag, so merge dates alone can double-count already shipped work; the inventory cross-checks both prior changelog PR numbers and commit ancestry against v0.6.7/main.
- Supersede chains can credit the carrying author instead of the original contributor; all 67 detected chains are resolved through their original PR bodies and authors.
- The migration skill could over-edit downstream code; automatic actions are limited to exact, provable source shapes and every ambiguous pattern is report-only.
- `UPGRADE_NOTES.md` may gain more entries while the PR is open; the final base-sync and review must re-check that all 0.7.0 notes remain classified.
